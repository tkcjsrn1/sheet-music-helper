# 작은 보표의 글꼴 최소 크기 후보 — 측정만 (2026-09-30)

RE:Aoharu 인쇄 이미지 1~3쪽의 라벨 711개를 사용했다. 현재 기본 글꼴은 보표에 따라 12~13px이다. 제품 파일은 바꾸지 않고 `renderer.py`의 글꼴 크기 계산식 중 최솟값 `1`만 메모리 속 사본에서 `14` 또는 `16`으로 바꿨다. 원본 이미지·라벨 JSON·확신도·배치 규칙·폰트·색은 동일하다. 사본의 현행값(최솟값 1)으로 재렌더한 세 PNG가 제품 결과와 모두 **픽셀 단위로 일치**하는 것을 먼저 확인했다.

| 최소 글꼴 | 실제 글꼴 | 커진 라벨 | 여백 포함 라벨 상자 겹침 쌍 | 음표↔라벨 중심 사이 마디선 넘김 | 글자 상자에 마디선 걸침 | 음표와 거리 >3sp |
|---:|---:|---:|---:|---:|---:|---:|
| 현행(1px 하한) | 12~13px | 0/711 | 0 | 0 | 0 | 3 |
| 14px 후보 | 14px | 711/711 | 0 | 0 | 1 | 3 |
| 16px 후보 | 16px | 711/711 | 0 | 0 | 0 | 4 |

겹침은 렌더러가 쓰는 글자 경계에 테두리·여백·확인 필요 점선 여백을 더한 사각형의 **양의 면적 교차 쌍**을 셌다. 마디선은 제품의 `barline_positions`를 같은 원본 영상과 음표 x좌표에 적용했다. 「마디선 넘김」은 제품과 같이 **음표 중심과 라벨 중심 사이**에 마디선이 있는 경우다. 별도 열의 「글자 상자에 마디선 걸침」은 더 엄격한 관찰 지표이며, 14px의 1건은 1쪽 보표 11의 음표 `(740,1890)`에서 라벨 x=714~728과 마디선 x=715가 겹친 경우다. 라벨 중심은 같은 마디에 남아 있다.

이 표는 Aoharu 조판과 당시 라벨·배치만 본 것이다. 14px 또는 16px의 가독성과 다른 악보에서의 결과를 증명하지 않는다. 당시에는 채택을 보류했고, 이후 사용자가 2026-09-30에 16px 적용을 지시했다.

## 16px 적용 전 추가 확인 — 저해상도 합성 사진 3장

사용자가 16px 적용을 지시한 뒤 확인했다. 기존 합성 촬영본 57장은 원본 sp가 19.25~20.75px여서 하한이 발동하지 않는다. 그중 M1을 통과한 **조건** 세 장(쇼팽 D♭ 1° 회전, 바흐 왼쪽 그림자, F장조 조표 픽스처 가우시안 잡음)을 0.60배 LANCZOS로 축소해 파생 입력을 만들었다. 세 파생 입력도 사진 모드 M1을 통과했고 보표 8개씩을 찾았다. 보정 후 저장한 영상·라벨 JSON을 동일하게 두고 렌더러 사본에서 이전 하한 1px과 새 하한 16px만 비교했다. 16px 사본은 실제 제품 사진 모드 PNG와 세 장 모두 픽셀 일치했다.

| 파생 입력 (보정 후 sp) | 라벨 | 하한 | 여백 포함 상자 겹침 쌍 | 음표↔라벨 중심 사이 마디선 넘김 | 글자 상자에 마디선 걸침 |
|---|---:|---:|---:|---:|---:|
| 바흐·왼쪽 그림자 (12.3~12.5px) | 194 | 이전 | 0 | 0 | 0 |
| 〃 | 194 | 16px | 0 | 0 | 1 |
| 쇼팽 D♭·1° 회전 (11.5~11.6px) | 290 | 이전 | 0 | 0 | 4 |
| 〃 | 290 | 16px | **2** | 0 | **8** |
| F장조·가우시안 잡음 (12.3~12.5px) | 165 | 이전 | 0 | 0 | 0 |
| 〃 | 165 | 16px | 0 | 0 | 0 |

쇼팽의 겹침 2쌍 중 1쌍은 배치 여백만, 1쌍은 글자 경계가 7×12px 교차하고 실제 글자 획도 4픽셀 교차한다. 따라서 **Aoharu의 겹침 0을 사진 입력에 일반화할 수 없다.** 마디선 넘김은 세 장 모두 0이지만, 글자 상자 걸침은 늘었다. 이 측정은 새로 축소한 *합성* 입력의 라벨 배치만 비교한다. 실제 사진의 가독성이나 음표 인식 정확도는 판정하지 않았다.
