# 음자리표 미검출 안내 — 렌더링·로그만 변경

저장 라벨의 flags에 clef_unknown이 하나라도 있으면 다음 문장을 표시한다.

> 음자리표를 찾지 못한 줄이 있습니다 — 그 줄의 계이름은 틀릴 수 있습니다

main.py의 변환/JSON 재렌더링, gui.py의 변환 로그와 공통 조표 머리말에 적용했다. 인식·판정·라벨 JSON·확신도를 바꾸지 않는다. 기존 알토 경고 함수는 유지하고 공통 경고 목록을 세 경로에서 사용한다. 같은 신호가 여러 번 있어도 경고는 한 번이다.

## 배치 확인

기존의 강제 줄바꿈을 두 경고에 모두 적용하면 실제 베토벤 표본의 상단 여백에 들어가지 않아 머리말이 생략됐다. 이를 layout-red.log 및 단위 검사로 재현한 뒤, 두 경고가 함께 있으면 각각 한 줄로 두었다. 조표+알토+미검출의 세 줄이 같은 상자에 배치된다. 기존 경고 한 개의 배치는 그대로다.

[실제 소스 결과의 상단 부분](alto_unknown_header.png): Beethoven Op.18 no.1 Bravura1쪽, clef_alto53개·clef_unknown21개. 두 경고와 조표가 겹치지 않는다. 악보 제목/본문을 덮지 않았고 PNG 변화는 첫 오선 y=176 위에만 있다. 전체 원본 악보/화면은 커밋하지 않았다.

합성 흰 종이 검사에서 두 경고+범례가 서로 겹치지 않고 악보 잉크를 덮지 않음을 확인했다. 상단 여백이 부족하면 기존 방식대로 머리말 전체를 생략하고 로그에는 경고와 여백 부족 안내를 남긴다. 지원 글꼴의 새 문구 글리프 검사도 포함한다.

## 회귀 범위

- source-comparison.json: 실제 새 변환 Aoharu1/D♭1/Beethoven1 JSON 전체가 기존9325fa8 exe 결과와 일치한다(라벨·음고·확신도·조표·음자리표 포함).
- relabel-comparison.json: 기존 실제 exe JSON8쪽을 새 소스로 재렌더링했다. 신호가 없는7쪽은 PNG 바이트 동일. 신호가 함께 있는 베토벤1쪽은 상단 경고만 변화. 입력 JSON8파일 바이트는 그대로다. 이8쪽을 다시 인식한 것으로 확대하지 않는다.
- tests/test_result_legend.py: 신호 유무/중복/동시 경고·글리프·배치·공간 부족 검사. feature-red.log는 구현 전 실패, layout-red.log는 강제 줄바꿈 반례다.
- tests/test_labels_cli.py: 기존22검사 통과, 재렌더링에서 두 경고 로그·사용자 수정 확신도 보존을 함께 확인했다(cli-tests.log).
