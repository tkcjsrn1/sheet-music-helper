# 여러 쪽 결과 넘기기 — 아침 화면 검토 대상

여러 이미지/소스 PDF를 변환한 뒤 미리보기 위의 이전/다음 버튼으로 성공한 쪽을 넘긴다. 현재 쪽의 세션·PNG·JSON·수정/되돌리기 기록·선택 영역을 함께 바꾼다. 실패한 입력은 기존 방식으로 목록에 보고하고 성공 쪽만 탐색한다. 변환 중에는 넘기지 않는다. 다음 쪽 파일이 사라졌다면 이전 결과를 유지한다.

- 01_first_page.png: 첫 성공 쪽.
- 02_edit_second_page.png: 다음 쪽 버튼으로 둘째 쪽에 가서 글씨 수정.
- 03_first_page_unchanged.png: 첫 쪽으로 돌아와 원래 라벨이 그대로임을 확인.

자체 생성 흰 이미지/라벨과 소스 Tk 위젯 검사로 캡처했다. exe 직접 클릭/사람 검증이 아니다. Computer Use 초기화는 `failed to write kernel assets: 지정된 경로를 찾을 수 없습니다. (os error 3)`로 실패했고 기존 소스 GUI 캡처 도구를 사용했다. 전체 원본 악보를 커밋하지 않았다.

재현: `python tests/test_gui_page_navigation.py --capture-dir docs/review/page_navigation`.
검사에는 현재 쪽 수정·쪽별 기록·되돌리기·원본 바이트 복귀·입력 선택 목록 유지·범위 밖/변환 중/파일 누락 거부가 포함된다. 기본 변환과 실제 2장 다쪽 변환의 PNG·JSON 바이트 대조 및 둘째 쪽 신고 ZIP의 원본/라벨 대조는 default_bytes.json에 기록한다.

쪽별 원본 프레임은 출력 폴더 안의 전용 TemporaryDirectory에 무손실 PNG로 캐시한다. 화면에 열린 쪽만 큰 이미지 배열을 유지한다. 새 입력/변환 때 해당 임시 폴더를 정리하고, 기존 사용자 산출물과 빌드는 건드리지 않는다. 1쪽이면 버튼을 숨기며 기본 설정과 PNG/JSON 형식은 그대로다. 인식·판정 변경과 새 의존성은 없다.

## 사용자 판단 필요·남긴 것

## 검사 중 정정

첫 전체 실행은 사진 모드 검사 대역(SimpleNamespace)에 새 `_clear_result_pages` 메서드가 없어 test_labels_cli.py의 두 하위 검사가 AttributeError로 실패했다. 메서드 대역과 호출 1회 검사를 추가해 실제 사진 모드 ON/OFF 검증을 유지했다. 제품에 `getattr` 우회나 오류 무시는 넣지 않았다. cli-test-double-red/green.log에 실패→22/22 통과를 남겼고 전체 검사를 다시 실행한다.

신고 ZIP 첫 비교는 기존 개인정보 제거(source.file→original.png)를 고려하지 않아 실패했다. original.png의 바이트와 선택 쪽 입력은 이미 같았으며, 기존 source.file 치환 한 항목만 정규화하고 나머지 전체 JSON을 비교해 통과했다. report-comparison-red.log와 default-check.log에 정정 근거를 보존한다. 이 값은 새 인식 오류나 쪽 혼합으로 세지 않는다.

사용자 검토 수정: 둘째 쪽에서 왼쪽 파일 이름이 입력1.png로 남는 오류를 기존#250 코드에서 재현한 뒤 공통 표시 경로에서 현재 쪽 파일 이름으로 갱신했다. 입력 선택 목록은 그대로다. page-name-red/green.log 및 새 화면3장으로 확인했다. 최신main 통합 후 전체36/36·실패0·건너뜀0, 실제2이미지 기본/다쪽 PNG·JSON 바이트 동일 및 현재쪽 신고ZIP 대조를 다시 통과했다. #249와 결합한 재열기 검사는 #250 병합 직후 다음 단계로 진행한다.
