# 조표·3/4 박자표에 붙은 유령 — 수정 전 재현

2026-10-05 사용자 제보. 최신main `444b3c4af78e832f6fcde60d9826b0f081ade1ea`에서 원본 Bravura 베토벤 4중주1쪽을 소스로 재처리해 재현했다. 제품 코드 수정은 아직 하지 않았다.

- 첫4보표 조표·박자표에 총16라벨. 각 보표 x313은 조표 ♭, x356의 세 라벨은 3/4 숫자 획이다. 위2보표의 「시b」는(313,212)/(313,392).
- 실제 이전53d674b exe와29037e2 exe의 위16개 좌표·표기가 모두 같다. 이번 링벽 수정이 새로 만든 현상이라고 분류하지 않는다. 기존 결과 검토에서 놓친 결함이다.
- 최종 `header_end=288`, 같은 원본의 `_timesig_span_end(...,288)=365`. 박자표 끝을 찾는 함수는 성공하지만 그 값이 최종 경계에 반영되지 않는다. 조표 교차투표 끝은288.4이며 첫보표의 실제 조표 막대는308 근처다.
- `_header_end_after`는 박자표 검출을 확장 허용 여부로만 쓰고 반환은 밀도식 `_extend_over_timesig` 결과다. 뒤 첫시스템 처리의 들여쓰기 조건을 못 통과하면 실제 숫자 끝365를 반영하지 않는다. 전용 인식 코드에서 확인할 경로다.
- TSV 첫시스템 정답 머리 최소x407.7. 쪽 전체 최소x325.4는 뒤 시스템이므로 이 둘을 혼동하지 않는다. 첫 높은음 두 보표의 실제 F4라벨(406,243)/(407,419)은 현재 모두 남아 있다.
- 주황점선으로 표시된 「시b」만 문제가 아니다. 숫자 획의 「미/도」는 caution으로 연하게 그려진다. check/caution을 일괄 숨기는 것은 실제 음표도 숨겨 해결책이 아니다.

[수정 전 부분 결과](before_detail.png), [원자료](before.json), [소스 로그](before-source.log).

```powershell
venv\Scripts\python.exe tools/check_header_symbols.py
venv\Scripts\python.exe tools/check_header_symbols.py --check
```

현재 `--check`는 유령16·첫실제F4 두 음표보존을 보고한 뒤 종료1이다. 일반 보고 명령의 종료0은 버그가 고쳐졌다는 뜻이 아니다. 이 검사는 이 입력의 기호상자300~365를 보는 고정 재현이며 제품의 새 판정 문턱이나 범용 삭제 규칙이 아니다. 수정 채택에는 이 사례 외에20쪽·Verovio 다른 조판·정답골든711·사진모드·첫음표 보존 대조가 필요하다.

## 수정 요청

`clef_keysig.py`는 COLLAB/AGENTS상 Claude 소유라 Codex 직접 편집하지 않았다. 사용자에게 이번 오류의 소유권 예외를 확인 중이다. 이관이 없으면 CLI가 기존 박자표 검출 결과를 경계로 반영하지 않는 경로와 첫시스템 판단을 고쳐야 한다. 문턱 숫자 완화·check 일괄삭제·좌표 고정 제품 필터는 쓰지 않는다. 정상 첫음표가 하나라도 없어지면 중단한다.
