## 포커스 재현의 정정

첫 수정 창 검사 실패를 Listbox 기본 문자 검색 충돌로 추측했으나 실제 이벤트를 기록하니 widget/focus가 Text였다(focus-trace.log). 창을 표시하기 전에 focus_force를 호출해 원래 로그에 포커스가 남았고 입력 보호가 정상 작동한 것이다. 설치된 Tk의 Listbox 일반 KeyPress 클래스 바인딩도 비어 있었다(class-binding.log). 창 표시 후 포커스를 주고 Canvas/Listbox 실제 대상까지 assert한 뒤 동일 기대값으로 검사하니 통과했다. 불필요하게 추가했던 목록 바인딩은 제거했다. 입력 보호를 우회하거나 기대값을 낮추지 않았다.

추가로 직렬 재검사에서도 키를 보내기 전에 Canvas 대신 루트 창이 포커스를 받은 실패를 확인했다(windows-focus-red.log). 설치된 CustomTkinter의 Windows 제목 표시줄 갱신은 예약된 포커스 복원 콜백을 쓴다. 검사에서 실제 대상/그 자식 위젯에 포커스가 잡힐 때까지 최대2초 안에서 확인하고 나서 키를 보낸다. 다른 위젯으로 바뀌면 그대로 실패하며 제품 입력 보호는 고치지 않았다. 새 창5회 키 검사 연속 성공(focus-stability.log), 이어 전체 GUI4검사 성공. 다른 GUI 변환과 병렬로 키보드 검사를 실행하지 않았다.
