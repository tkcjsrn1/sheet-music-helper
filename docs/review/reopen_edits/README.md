# 저장한 수정본 다시 열기 — 아침 화면 검토 대상

새 수정본 폴더를 선택한 다음 원본 악보를 선택한다. 원본 SHA-256과 편집 프레임의 SHA-256, 최종 JSON과 수정 기록, 재렌더링 PNG의 픽셀을 확인한 뒤에만 화면을 바꾼다. 다시 변환하지 않고 수정·삭제·추가 기록을 이어서 되돌린다. 실패/취소 시 이전 결과를 유지한다.

- 01_before_open.png: 열기 전.
- 02_reopened.png: 수정·삭제·추가가 저장된 폴더를 버튼으로 다시 연 결과.
- 03_continue_undo.png: 다시 연 뒤 마지막 추가를 되돌리고 수정 목록을 연 상태.

세 화면은 자체 생성 흰 이미지와 라벨만 사용한 소스 Tk 위젯 검사다. exe 직접 클릭/사람 검증이 아니다. Computer Use 초기화는 `failed to write kernel assets: 지정된 경로를 찾을 수 없습니다. (os error 3)`로 실패했다. 기존 소스 GUI 캡처 도구를 사용했고 검거나 단색인 캡처는 거부했다.

재현: `python tests/test_gui_reopen_edits.py --capture-dir docs/review/reopen_edits`.
기본 변환 전후 Aoharu1/D♭1의 PNG·JSON 전체 바이트 대조는 default_bytes.json에 기록한다. 수정 없을 때 원래 PNG·JSON 경로와 바이트를 그대로 반환한다. 원본 누락/해시 불일치/손상 기록/JSON-기록 불일치 거부, 연속 세 번 되돌리기로 원본 바이트 복귀를 검사한다.

## 사용자 판단 필요

1. 재열기 메타데이터가 없는 예전 3파일 수정본은 거부한다. 지워진 라벨·원본 라벨 위치를 최종 JSON에서 추정하지 않는다. 원본을 다시 변환하고 수정본을 새로 저장하는 안내를 보여준다.
2. 이번 PR은 병합하지 않는다. 화면과 폴더 선택→원본 선택 흐름을 아침에 확인한 뒤 결정한다.

추가되는 인식원본.json·편집원본.png·재개정보.json은 사용자 수정/영역 저장 때만 생성한다. 기본 변환 파일에는 추가 필드나 바이트 변경이 없다. 저장 후 다른 PC에서 같은 글꼴이 없어 재렌더링을 못 하면 이유를 표시하고 열지 않는다.
