Codex가 토큰 한도로 멈춰 CLI가 이어받았다(사용자 지시 — Codex 소유 `gui.py` · 테스트 수정 허용, WORKLOG 「Codex 검토 요청」).
코드는 Codex 작업 공간(`F:\akbo-data\tmp\audio-highlight-delay-20261104`)의 미커밋 수정을 그대로 옮겼다. CLI는 로직을 바꾸지 않았다.

## 문제

`label_audio.play_piano`는 MIDI 「건반 누름」을 보낸 직후 `on_group('start')`를 알린다. 그런데 Microsoft GS Wavetable Synth는 자체 버퍼 때문에 소리가 그보다 늦게 나간다.
8df72c9 실측(#458 `AUDIO_MEASURE.md`)에서 화면 강조가 소리보다 약 161 ~ 187ms 먼저 나왔다. 음원의 실제 출력 시각을 알려 주는 API는 없다.

## 고침(`gui.py`)

- 재생 스레드가 `start` · `end` · `finished` 사건에 송신 시각(`time.perf_counter()`)을 붙인다.
- GUI는 그 사건을 **송신 시각 + 220ms**에 표시하도록 `after`로 예약한다(`_schedule_audio_event`). UI 큐 대기(80ms 주기)는 지연에 더해지지 않는다. 이미 늦은 사건은 바로 표시한다. `plan` · `log`는 바로 처리한다.
- 「듣기 중지」 때 예약을 모두 취소한다. 세대 토큰이 다른 늦은 예약은 다시 켜지지 않는다.
- 220ms의 근거: 같은 측정 세션에서 고정 180ms(v3)는 1배 · 0.5배에서 95분위가 50ms를 넘었다. 220ms(v4, 아래)는 중앙값이 0 근처다.
- 한계: 값은 이 PC의 기본 출력 장치 실측이다. 블루투스 등 지연이 큰 장치에서는 소리가 더 늦을 수 있다. 장치별 자동 보정은 하지 않는다.
