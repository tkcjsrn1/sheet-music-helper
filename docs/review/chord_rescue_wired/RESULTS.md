# 붙은 화음 구제 연결 검증 (2026-09-30)

상위 PR #104의 `chord_rescue.py`를 `main.py`와 `gui.py`의 공통 함수로 연결했다. 사진 모드가 켜지면 두 번째 검출은 실행하지 않는다. `notehead_detect.py`·`verify.py`·`chord_rescue.py`는 수정하지 않았다.

| 확인 | 실제 제품 경로 결과 |
|---|---:|
| `tests/run_all.py` | 16개 통과 · 건너뜀 0 · 실패 0 |
| Aoharu 3쪽 실제 CLI JSON ↔ 골든 TSV | 226 + 327 + 158 = 711줄 일치, 추가 0 · 삭제 0 |
| 검증 20쪽 새 라벨 / 가운데 유령 삭제 | 305 / 44 |
| 붙은 화음 누락 | 269/522 → 30/522 |
| 기존의 맞는 라벨 소실 | 0 |
| 새 라벨의 `chord_rescue_added` 표시 | 305개 모두 최소 `caution`(주의). 다른 신호가 겹치면 `check` |

20쪽 수치는 `main.run_page()`를 각 쪽에 실제 실행하고 결과 JSON을 PDF 글리프 정답과 대조했다. Aoharu는 실제 출력의 보표·좌표·음고·임시표·표기를 골든 TSV의 앞 여섯 열과 직접 비교했다. 실제 제품 결과의 `check`는 총 299개다. 추가 305개 중 295개는 `caution`, 10개는 다른 확인 신호가 겹쳐 `check`다. 측정기는 다른 진단 경로를 써서 PR #104의 `check` 212개와 이 값을 직접 비교할 수 없다.

대표 D♭ 1쪽 한 번 실행의 처리 시간은 구제 경로를 끈 경우 3.34초, 켠 경우 5.20초였다. 단일 실행이므로 성능 보장은 아니다.

검토 그림: [쇼팽 D♭ 1쪽](chopin_Db_p1.png), [쇼팽 B♭m 4쪽](chopin_Bbm_p4.png). Claude의 눈 판정 전까지 이 그림을 정답 확정 근거로 쓰지 않는다.

상위 PR #104는 사용자 조건(추가 라벨 주의 표시·사진 모드 제외)을 반영해 main에 병합됐다. 이 연결 PR은 그 최신 main 위에서 진행한다.
