## 기본 출력 대조 방법과 한계

[기준 git blob 정보](baseline-main.json)의 고정 SHA에서 note_namer.py·label_audio.py 원문을 바이트 그대로 보존했다. 두 모듈 이외 제품 코드가 그 기준과 같음을 먼저 확인한 다음, [기준 실행기](run-baseline-main.py)가 별도 프로세스에서 기준 두 모듈을 읽고 같은 main.py를 실행한다. [대조 도구](check-default-bytes.py)는 그 기준 실행과 소비층 실행을 같은 입력·새 폴더에 차례로 돌려 PNG/JSON 원문 바이트를 비교한다. 파일 해시를 보존했고 기존 결과를 재사용하지 않았다. 제품 파일/인식 함수를 바꿔 끼우거나 원본 악보를 커밋하지 않았다.

이 도구들은 저장소 루트에서 output/double-acc-standalone-20261018/ 아래의 기준 소스/해시와 함께 실행한 원자료다. 재실행 시에는 기록된 커밋의 git blob을 변환 없이 같은 폴더에 준비하고 새 출력 폴더를 사용해야 한다. 기존 결과나 다른 main을 쓰면 확인을 거부한다. 입력3개와 SHA는 default-bytes.json에 있다.

이는 **아직 실제 bb/## 종류를 연결하지 않은 소비층의 비대상/기본 동작 검증**이다. 실제 겹임시표49쪽 표기 변화·헛검출/취소·schema2 저장/재열기 검증을 대신하지 않는다. 전체 검증 뒤 제품·검사 파일 SHA가 변하지 않았음을 verification.json에 남겼다. 주황 check는 그대로이며 종류 확인만으로 확실로 올리지 않는다.
