# 신고 원본과 라벨 JSON의 해시 일치

기준 main `77be4ba`. 변환 후 원본 이미지가 외부에서 바뀌면 신고 ZIP은 성공 저장되지만 재현 도구가 원본 SHA-256 불일치로 거부했다. [기존 GUI 저장 콜백의 실패 검사](before.log), [유효한 자체 PNG로 기준 코드·수정 코드 대조](before-after-data.json)에서 확인했다. 실제 악보/사용자 파일은 건드리지 않았다.

공통 저장 함수가 원본을 한 번 읽고 그 사본의 SHA-256을 라벨 JSON과 비교한다. 불일치나 누락 해시는 원본을 다시 변환하라는 ValueError 안내로 거부하며 기존 신고 ZIP과 입력 파일을 유지한다. 같은 사본을 ZIP에 넣으므로 검사 후 원본이 바뀌어도 신고 원본·라벨 해시는 일치한다. 기존 check_source는 경로의 파일을 읽는 함수라 이후 ZIP 읽기까지 고정하지 못하며, 읽기/해시/묶기는 표준 라이브러리와 기존 재현 도구의 해시 비교 방식을 사용했다. 새 도우미/의존성 없음.

정상 신고 저장→재현, 변환 후 원본 변경 거부·기존 ZIP/입력 보존, 해시 누락 거부, ZIP 기록 순간 원본 변경에도 검증한 사본 재현 통과. 네 파일 구성·익명 파일명·원본/라벨 내용 유지. ZIP 컨테이너의 바이트 동일성은 주장하지 않는다. 원본 한 파일 크기만큼 메모리에 보관하며 큰 파일 신고가 필요하면 검증한 임시 사본 방식이 대안이다.
