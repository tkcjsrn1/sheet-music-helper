# 완료되지 않은 GUI 변환 결과의 혼합 저장

기준 main 706f2e5. 실제 소스 Tk GUI와 기존 변환 파이프라인을 사용했다. exe를 직접 클릭한 검증은 아니다.

1. 기존 입력을 변환하고 첫 라벨을 사용자 수정하여 별도 수정본 PNG·JSON을 저장한다.
2. 동일 원본의 두 이미지 변환을 시작한다. 편집 캐시 프레임 저장에만 OSError를 주입한다. 인식·출력 PNG·라벨 JSON 저장은 실제로 실행한다.
3. 두 쪽 모두 실패한 뒤 저장 버튼을 호출한다. 기존 코드는 이전 수정 PNG와 새 미수정 JSON을 신고 ZIP으로 저장했다. 원본 SHA가 같으므로 원본 일치 검사로는 막히지 않는다.
4. 회귀 검사가 기존 코드에서 결과 상태가 남는 지점에 실패했다. 수정 후 완료된 결과가 없으면 결과 경로·편집/쪽 상태·미리보기를 비우고 저장/편집 버튼을 비활성화한다. 기존 수정본 파일은 삭제하지 않는다.
5. 저장 실패를 제거하고 재시도한 결과는 최초 기본 PNG·JSON과 바이트 동일, 두 성공 쪽 유지, 기존 수정본 바이트 동일이다. 일부 쪽 실패 후 성공 쪽 유지 검사는 기존 다쪽 검사로 별도 통과했다.

완료 여부는 GUI 출력 공개 단계에서 판단한다. 합친 PDF 작성까지 실패하면 GUI 결과를 공개하지 않으며, 이미 생성된 개별 출력 파일은 디스크에 남는다. 실패 직전 편집 세션을 메모리에서 복원하는 기능을 추가하지 않았다. 저장된 수정본은 기존 재열기 기능으로 열 수 있다.

자료: before-data.json, failing-test.log, fixed-test.log, partial-pages.log, final-tests.log. 로그의 Tk after 콜백 종료 메시지는 기존 검사 앱 파괴 후 남은 예약 콜백에서 발생했으며 성공/실패 판정은 마지막 assertion과 프로세스 종료 코드로 확인했다. 원본 악보·exe·ZIP은 포함하지 않았다.
