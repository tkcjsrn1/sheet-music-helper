# D-3 라벨 편집 1차 검토

기준 main: `00a1fd3` (♮·♯ #149, G1 #150, A-25 사전 측정 #151 포함. A-25 제품 수정은 미병합).

## 이번 범위

결과의 실제 글씨 상자를 클릭하거나 「라벨 수정 / 삭제」 목록에서 골라 표시 글씨를 바꾸거나 삭제한다. 마지막 수정부터 되돌릴 수 있다. 수정은 재인식을 실행하지 않고 현재 미리보기 쪽에만 적용한다. 여러 쪽 실행은 기존처럼 첫 성공 쪽을 미리보기로 연다.

수정마다 output 아래 새 `사용자수정-<고유값>` 폴더에 `결과.png`, `라벨.json`, `사용자수정.json`을 함께 저장한다. 임시 폴더에 세 파일을 완성한 뒤 공개하며 원래 PNG·JSON은 덮어쓰지 않는다. 라벨 JSON의 변경된 글씨는 `edited: true`, 수정·삭제 이력은 `user_edits`와 별도 사용자수정 파일에 「사용자 수정」으로 남는다. 마지막 수정을 취소하면 원래 PNG·JSON 경로와 바이트로 돌아간다. 「수정본 폴더를 다른 곳에 저장」은 세 파일을 함께 내보낸다. 기존 「다른 이름으로 저장」은 지금처럼 PNG만 복사한다.

**후속 범위:** 기존 수정 파일을 GUI에서 다시 불러오기, 재인식 결과로 수정 이월은 아직 구현하지 않았다. 빈 자리 추가는 아래 GUI 2차에 포함했다. 데이터층의 추가 API는 그대로 보존했다. 글씨 수정은 `text`만 바꾸고 `pitch`·임시표·조표·원래 확신도는 JSON에 그대로 보존한다. 사용자 수정(`edited: true`) 라벨은 그림에서 `certain`과 같은 진한 글씨로 표시하며 주황 점선을 그리지 않는다. CLI `--relabel`도 같은 규칙을 쓴다. 별도 색을 추가하지 않아 기존 범례는 그대로 유효하다. 삭제한 라벨은 JSON 목록과 그림에서 빠지고 이전 표기는 수정 기록에 남는다.

## 그림

- `01_before.png`: 수정 전 실제 GUI.
- `02_editing.png`: 선택 라벨의 파란 상자와 편집 창. 예시로 D♭ 1쪽 (1694,618) B3 「시b」를 「미」로 입력했다.
- `03_saved.png`: 저장 뒤 실제 GUI. **동작 시연을 위한 임의 표기 수정이며 음악 정답 교정이라고 주장하지 않는다.**
- `saved_result.png`: 같은 시연의 전체 저장 PNG.
- `edited_example.json`, `edits_example.json`: 같은 시연의 저장 데이터. 변경 좌표·이전/이후 글씨·`edited`·삭제 이력 형식을 확인할 수 있다.

Windows Computer Use 도구는 `failed to write kernel assets` 초기화 오류로 쓸 수 없었다. `tools/check_label_edit_gui.py`가 확대/스크롤한 실제 Tk 캔버스에 `<Button-1>` 이벤트를 보내 편집 창과 정확한 대상 선택을 확인하고 Pillow로 앱 영역을 화면 캡처했다. 다른 창이 가린 초기 캡처는 버리고, 테스트 앱과 편집 창을 앞에 둔 캡처 세 장을 다시 열어 확인했다. 그려 만든 목업이 아니다. 사진은 검은 화면이 아니며 개인 앱·작업 표시줄을 제외했다. 사람이 직접 마우스·키보드로 사용한 검증은 별도다.

재현: `python tools/check_label_edit_gui.py --baseline-dir output/d3-before-gui --capture`. 기준선 폴더는 변경 전 GUI `_convert_page`로 기본 설정(고정도·사진 OFF·범례 ON·맑은 고딕18)을 적용해 Aoharu 1쪽과 D♭ 1쪽의 PNG·라벨 JSON을 먼저 저장한 것이다. 수정 후 네 파일이 모두 바이트 일치했다. 기준선 없는 실행은 거부한다.

20쪽 제품 경로 대조: 추가0·삭제0·음고0·표기0·조표/음자리표 문맥0·음자리표 끝0. 기준선 Aoharu 3쪽의 골든 좌표·음고·고정도 표기 711/711도 확인했다. 보표·적용 반음·이동도·PDF 스냅샷은 전체 골든 회귀 검사로 별도 검증한다. 골든과 PDF 스냅샷 파일은 변경하지 않는다.

**PR #153 판정 반영:** Claude 기능 동작 통과 및 사용자 지시대로 수정 라벨의 점선을 제거하고 직접 클릭 선택을 확인했다. 갱신된 화면 세 장은 같은 좌표의 원래 check→편집 입력→진한 글씨 저장을 보여준다. A-25 호출부와 금지 파일은 바꾸지 않았으며, 이 변경은 다음 베타에 포함한다. A-25 제품 병합 알림 전 새 빌드는 계속 대기한다.

전체 검사: `python tests/run_all.py` 25/25 · 실패0 · 건너뜀0. 기준과 수정 후 PNG/JSON SHA-256도 네 파일 모두 일치했다. 초기 사진 토글 단위 검사 더블에 새 컨트롤이 없어 오류2가 났으며 더블에 편집창 닫기·버튼만 추가한 뒤 전체 검사를 다시 실행했다. 기존 판정/기대값은 바꾸지 않았다.

## PR #153 수정 검증 (2026-10-03)

GUI와 CLI 재렌더링의 점선 문제를 먼저 실패하는 검사로 재현한 뒤, `modules/label_edits.display_confidences()`로 그리기 값만 공유했다. 수정 전 check였던 라벨의 저장 PNG가 같은 라벨을 certain으로 그린 PNG와 바이트 일치하며 삭제한 라벨은 포함하지 않는다. JSON의 원래 check와 pitch, 이전/이후 글씨 및 사용자 수정 기록은 그대로 남는다. 실제 캔버스의 클릭 바인딩도 확대·스크롤 상태에서 선택한 라벨을 정확히 열었다. 편집하지 않은 Aoharu p1·D♭ p1의 PNG/JSON 네 파일은 이전 결과와 바이트 일치했다. 수정 후 전체 검사도 25/25·실패0·건너뜀0이며 골든711·PDF17쪽 스냅샷 변화0이다. 갱신한 화면 세 장을 직접 열어 점선 제거와 다른 창 가림 없음을 확인했다.

20쪽 전체 스냅샷 객체도 완전히 일치했다(허용 거리 내 매칭만이 아니라 좌표·filled·확신도를 포함한 모든 저장 필드 비교). 명령 출력은 `verification.log`에 남겼다.
