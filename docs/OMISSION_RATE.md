# 오삭제율 — 음표 → 라벨 방향으로 센 네 쪽 (2026-09-22)

지금까지 오류율 표의 오삭제 칸은 「모름」이었다. 라벨을 원본과 대조하는 전수 판정은 **사라진 음을 셀 수 없다**
(`MEASUREMENT_PITFALLS.md` C-4). 여기서는 정답 음표 머리를 먼저 정하고 결과 라벨과 1:1로 짝지었다.

- 기준 코드: PR #62 브랜치(`claude/accidental-filled-check`, 임시표 18건 수정 반영). main 반영 174ffb1(2026-09-22)
- 도구: `tools/measure_omission_rate.py` (제품 코드 읽기만)

### RE:Aoharu — 「오류 0%」는 오삭제까지 0이었다

예전 전수 판정은 라벨 기준이라 오삭제를 볼 수 없었다. 이번에 보표 12개를 원본 위 라벨 표시로 전부 훑었다 —
**라벨 없는 음표 머리 0개.** 띠 그림 범위(보표 위 4sp) 밖으로 잘린 높은 음 `(507,1723)` A6도 따로 확인했다(라벨 있음, 음고 맞음).
유령·음고는 기존 전수 판정 결과(0)를 그대로 쓴다.

## 2. 정답을 어떻게 정했나

- **PDF 세 쪽**: PDF 안의 음표 머리 글리프(`noteheads.*`)를 직접 읽었다(CFF 윤곽 중심, 300dpi). 음고는 그 중심의
  오선 반칸 위치 + **PDF의 음자리표 글리프**. 사람 눈은 불일치 자리(총 104자리)를 전부 확대해서 판정했다.
- 정답에서 뺀 것:
  - **같은 자리 글리프 두 개** — 두 성부가 같은 음을 공유해 머리가 하나로 보인다(B♭m 1쪽 `(2332,1436)`). 라벨 하나가 맞다
  - **다른 글자 크기의 머리** — 꾸밈음(13pt대, 지원 범위 밖)과 빠르기 표시 `♩.=` 속 음표(D♭ `(909,484)`, 오선 밖 필터가 옳게 지움)
- **RE:Aoharu**: PDF가 없어 사람이 확대 그림으로 셌다.

**음고 오류는 음이름+옥타브만 대조했다.** 임시표까지 포함한 최종 표기는 Aoharu·바흐·D♭ 1쪽은 예전 전수 판정(오표기 0),
B♭m 1쪽은 **독립 판정을 안 했다**(피해 18개의 표기만 확인).
