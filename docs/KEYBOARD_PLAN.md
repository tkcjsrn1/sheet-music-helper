# 2단계 건반·재생 위치 — 사전 조사 초안

상태: **읽기 조사와 설계 제안, 구현 없음**. 2026-10-18 기준 조사 내용에 e141908 베타 검증/보고(#401) 완료 상태를 구분해 추가했다. 사용자 지시로 10-19 문서 PR에 올린다. 건반 표시·시간 정보·진행 callback은 아직 제품 계약이 아니다.

## 1. 현재 구조 — 코드에서 확인한 사실

코드 읽기 기준 main `718abd3`(아래 마지막 원격 상태 갱신과 구분). [label_audio.py](../modules/label_audio.py), [gui.py](../gui.py), [label_audio 검사](../tests/test_label_audio.py), [D-2 현재 범위](D2_PITCH_AUDIO.md)를 읽었다. 다음은 현행 설명이며 제안 기능이 이미 구현됐다는 뜻이 아니다.

### 데이터 → 재생 순서

1. GUI `_listen_labels`(1818행 부근)는 변환 중/결과 없음이면 거부하고, 재생 스레드가 살아 있으면 중복 시작을 거부한다.
2. 현재 쪽의 `_edit_session['doc']`를 **deepcopy**해 당시 결과를 고정한다. 영역 선택 결과가 들어간 현재 doc이므로 영역이 있으면 그 라벨 목록, 없으면 현재 쪽 전체다. 모든 쪽 연속 재생은 아니다.
3. 현재 「확인 필요 음은 듣기에서 제외」 값을 읽고, 새 `threading.Event`와 daemon worker를 만든다. `_audio_worker`는 `audio_groups`로 묶고 `play_piano`를 부른다.
4. `audio_groups`는 라벨마다 음높이를 변환하고 **(staff // 2, 정확한 x좌표)**를 키로 묶는다. 키를 정렬해 시스템 쌍 순서 → 왼쪽부터 처리하고, 각 묶음의 MIDI 정수를 정렬한다. 두 보표씩 피아노 한 시스템이라는 가정이며 실제 악기/성부/손 정보를 판독한 것은 아니다.
5. 같은 키의 MIDI는 set으로 중복을 없앤다. 같은 음높이의 라벨이 둘 있어도 소리는 한 번이다. 다른 옥타브는 다른 MIDI이므로 남는다. x가 가까워도 정확히 다르면 다른 묶음이다. 이 방식은 실제 음악의 동시성이나 박자를 보장하지 않는다.
6. `skip_check=True`이면 check이면서 edited가 아닌 라벨을 제외한다. caution은 남고 사용자 수정 라벨은 원래 check여도 남는다. 잘못된 음고/표기는 이유와 함께 제외한다. 한 묶음의 전부가 제외되면 그 묶음은 없어져 쉼표나 원래 시간 자리는 남지 않는다.
7. 반환은 **MIDI 목록들의 목록 + 제외 사유 목록**이다. 재생된 음과 원래 라벨 번호의 대응은 반환하지 않는다. 서로 다른 이명동음 라벨도 같은 건반/같은 소리로 합쳐질 수 있으므로 MIDI에서 라벨을 역추정하면 틀린다.

### 실제 소리와 현재 위치

- `play_piano(groups, cancel, duration=.28)`(90행 부근)는 Windows WinMM을 ctypes로 열고 Microsoft GS Wavetable Synth의 GM Acoustic Grand Piano(program0)를 선택한다. 새 음원 파일/라이브러리를 배포하지 않는다.
- 각 묶음의 note-on을 연속 전송하고 `cancel.wait(.28)` 뒤 note-off를 전송한다. 여러 note-on은 하나의 원자적 메시지가 아니라 같은 묶음에서 연속 호출된다. 현재는 모든 묶음이 같은 길이인 **음높이 확인** 기능이다. 악보 음 길이·쉼표·타이·성부 재생이 아니다.
- 반복문의 내부에서는 현재 묶음을 알지만 GUI가 받을 진행 callback/라벨 번호/시간 정보가 없다. 함수 반환은 None이고 GUI에는 시작 묶음 수·제외/오류 로그만 있다. 시작부터 흐른 시간을 .28로 나눠 현재 위치를 추측하면 장치 열기 지연·처리 시간·취소를 놓친다.
- `finally`에서 reset/close를 수행하고 재생·정리 실패를 알린다. `_stop_listening`은 취소 Event만 set하며 GUI를 기다리게 하는 join은 없다. 다음 시작은 기존 스레드가 실제로 끝날 때까지 거부한다.
- 호환용 `write_wav`는 사인파 WAV 생성 함수지만 GUI 피아노 재생은 이 함수를 쓰지 않는다. 건반 표시를 위해 WAV 경로로 바꾸지 않는다.

### 현재 GUI에서 관련된 상태

- `preview_frame`: row0 쪽 표시, row1 확인 필요 순회, row2 미리보기/세로 스크롤, row3 가로 스크롤. row2만 확장된다.
- `_redraw_preview`(1352행 부근)는 원본 미리보기 이미지를 확대/축소하고 Canvas를 비운 뒤 이미지·선택 라벨·영역을 그린다. 재생 때마다 이 이미지 전체를 다시 그리는 방식은 피한다.
- `_review_index`와 `_selected_preview_box`는 **단일 검토 선택**용이다. 같은 위치/음고/표기의 중복을 출현 번호로 대응시킨다. 재생 화음 전체를 담는 상태가 아니므로 재생 위치로 이 값을 덮어쓰지 않는다.
- 현재 라벨 클릭은 `_on_label_click`에서 수정 창 선택/빈 곳 추가를 수행한다. 클릭 자체가 피아노 재생 시작은 아니다. 기존 편집 동작을 건반 기능으로 가로채지 않는다.
- 쪽 전환, 수정본 다시 열기, 앱 종료는 `_stop_listening`을 부른다. `_apply_label_changes`(1758행 부근) 자체에는 중지 호출이 없다. 따라서 복사한 예전 doc의 소리를 내는 도중 화면 doc이 바뀔 가능성이 있다. 실제 결함 재현은 이번에 하지 않았고, 새 강조 기능 설계에서 막아야 할 상태다.

## 2. 건반 위치·음역·새 의존성 제안

### 우선안

- 미리보기 아래(row3 가로 스크롤보다 아래)의 얇은 패널에 **기존 tkinter.Canvas**로 흰/검은 건반과 현재 음 이름을 그린다. 새 패키지·샘플·폰트 파일은 필요 없다. 기존 ctypes 피아노 엔진도 그대로 사용한다.
- 왼쪽 주요 파일/변환 버튼을 아래로 더 밀지 않는다. 700px 높이에서 화면을 얼마나 차지할지 확인하고, 결과가 없을 때 숨김/작은 화면에서 접기 같은 UI 세부는 실제 시안으로 정한다. 이번에는 창이나 시안을 렌더하지 않았다.
- 첫 안은 피아노 **88건반 A0~C8(MIDI21~108)**의 고정 음역이다. 음마다 표시 음역이 바뀌는 자동 창 이동을 피하고 건반 위치를 일관되게 유지한다. 좁은 화면에서 너무 작으면 가로 스크롤이 가능한 폭을 두는 안을 비교한다. 최소 건반 폭/패널 높이는 아직 실측·채택하지 않았다.
- 모든 건반에 글자를 채우기보다 도(C)와 옥타브 기준 및 별도 현재 음 이름 표시로 가독성을 검토한다. 현재 표기 레bb/파##와 실제 눌리는 건반 이름이 다를 수 있으므로 **원래 라벨 표기**와 실제 MIDI 건반을 구분해서 보여 준다.
- 기존 재생은 MIDI0~127을 허용한다. 88건반 밖의 유효 음은 소리를 바꾸거나 조용히 숨기지 않고 「표시 음역 밖」과 음높이를 알린다. 건반 범위에 맞추려고 옥타브를 이동하거나 입력을 잘라내지 않는다.
- 악보 보표 번호를 손으로 단정하지 않는다. 첫 단계는 활성 건반 표시와 음 이름만으로 시작하고, 정확한 손/파트 구분이 없는 상태에서 왼손·오른손 자동 색 구분은 약속하지 않는다.

### 일부 음역을 먼저 쓰는 대안

현재 쪽에서 쓰는 음역 중심의 일부 건반만 그리면 작은 창에서 읽기 쉽다. 대신 쪽마다 기준이 달라지고 양끝 밖 음/넓은 화음/옥타브 경계 처리와 사용자의 위치 혼동을 검증해야 한다. 우선 고정88안을 검토하되 좁은 화면 판정 뒤 선택한다. 두 방식을 모두 제품 옵션으로 넣기로 결정한 것은 아니다. 건반을 눌러 별도 연주하는 기능도 이번 필수 범위는 아니다.

## 3. 재생·라벨·건반을 같은 사건에 연결하는 안

아래 명칭과 자료형은 협의용 제안이며 확정 API/작성된 코드가 아니다. 핵심은 소리와 화면이 **하나의 고정 재생 계획**을 공유하는 것이다.

### 3-1. 원래 라벨을 잃지 않는 계획

- 현재와 같은 필터·묶음·음높이 계산에서, 묶음 키/순서, 고유 MIDI 목록, 각 음에 해당하는 **재생 시작 시점 snapshot의 라벨 번호 목록**을 함께 보관한다. 그룹마다 별도 화면 자료를 x 근접이나 MIDI만으로 다시 만들지 않는다.
- 기존 `pitch_to_midi`를 단일 음높이 계산 근거로 쓴다. 건반 표시용 새 조표/이동도/겹임시표 계산기를 만들지 않는다. 글자만 보고 자동 인식 음높이를 역산하지 않는다.
- 기존 `audio_groups`의 반환과 제외 정책을 깨지 않는 확장안을 정한다. 필요하면 같은 내부 그룹 생성 결과를 기존 MIDI 반환과 새 메타데이터 반환이 공유한다. 같은 계산을 두 구현으로 복제하지 않는다.
- 중복 MIDI는 소리·건반은 한 번, 라벨 강조는 해당하는 여러 라벨을 모두 유지한다. 라벨 id나 좌표가 중복될 수 있으므로 id만으로 하나를 고르지 않고 snapshot 인덱스/출현 번호와 placements를 대응시킨다.

### 3-2. 재생 사건 → GUI

- 재생 엔진의 선택적 진행 알림으로 묶음 시작/끝과 종료·오류를 전달하는 안을 검토한다. 시작은 그 묶음의 note-on 전송 성공 후, 끝은 note-off 후 알린다. 장치 열기나 note-on 실패를 재생 성공으로 표시하지 않는다.
- worker에서는 Tk 위젯을 만지지 않고 표준 라이브러리 `queue`에 사건만 넣는다. 메인 스레드가 시작한 하나의 `after` 펌프에서 라벨·건반을 함께 갱신한다. 별도 그림 타이머와 소리 타이머를 각각 돌리지 않는다.
- 묶음 시작 사건 하나로 해당 라벨 여러 개와 활성 MIDI 건반을 함께 표시하고, 끝 사건에서 함께 해제한다. 여기의 진행 숫자는 「음높이 묶음 n/전체」로 표시해 박자/마디나 기존 「확인 필요 n/전체」와 혼동하지 않는다.
- 이는 **재생 명령과 UI의 동기화**다. WinMM/드라이버의 실제 소리 지연과 Tk 처리 지연까지 0이라고 주장하지 않는다. 이후 실제 루프백과 사건 시각을 비교하고 지연이 보이면 근거를 남긴다.

### 3-3. 기존 미리보기·편집과 공존

- 검토/수정 선택과 분리한 재생 활성 라벨 집합을 둔다. 재생 때문에 `_review_index`나 편집 창의 입력·선택을 강제로 바꾸지 않는다. N/P는 기존 확인 필요 순회 동작을 유지한다.
- Canvas의 별도 재생 태그로 강조 사각형을 추가/삭제한다. 원래 check 점선·주의 옅기·사용자 수정 글씨를 바꾸거나 확신도를 승격하지 않는다. 색뿐 아니라 윤곽으로도 위치를 구분한다.
- 건반 및 재생 태그만 갱신하고 매 묶음마다 `_redraw_preview`로 페이지 전체 리사이즈를 반복하지 않는다. 확대/축소 때 기존 redraw가 Canvas를 비우므로 활성 snapshot/라벨 집합에서 오버레이를 다시 그릴 수 있어야 한다. 원본 좌표→zoom/scroll 변환은 기존 placements/Canvas 방식을 따른다.
- 선택 라벨은 기존 편집 의미를 유지하면서, 그 라벨의 유효 음높이를 건반에 표시하는 보조 동작을 검토할 수 있다. 건반을 보여 주려고 자동 재생하거나 기존 클릭 선택을 없애지 않는다.
- 저장 PNG·labels JSON·신고 ZIP의 결과 파일에는 재생 강조를 굽지 않는다. 재생을 시작하지 않았을 때와 저장된 변환 결과의 바이트를 유지한다.

## 4. 중지·건너뜀·상태 변경

| 상황 | 현재 상태/유지할 정책 | 새 강조 기능에서 필요한 처리 |
|---|---|---|
| 듣기 중지/정상 끝/실패 | cancel 및 WinMM finally 정리 | 메인 스레드의 활성 라벨/건반/진행 표시를 함께 해제. 오류·빈 계획·정리 실패도 같은 종료 경로를 지나야 함 |
| 이미 재생 중 다시 시작 | 살아 있는 스레드면 거부 | 기존 안전장치 유지. 이전 엔진이 정리되기 전 새 장치를 겹쳐 열지 않음 |
| 쪽 전환/입력 변경/새 변환/수정본 열기 | 일부 경로만 기존 중지 호출 있음 | 표시 대상 교체 전에 재생을 취소하고 화면 사건을 무효화. 실패해서 이전 페이지를 유지하는 경우도 일관된 상태로 남김 |
| 수정/추가/삭제/되돌리기/영역 변경 | 시작 당시 문서 사본은 바뀌지 않음 | 오래된 소리와 새 화면이 섞이지 않도록 중지→사건 무효화 후 편집 적용하는 안을 우선. 실시간 계획 재작성은 이번 범위에 넣지 않음 |
| check 제외/해석 불가 | 해당 라벨 제외, 전부 빠진 묶음은 삭제 | 제외 라벨은 연주 중 강조하지 않음. 일부 화음만 남으면 남은 소리/라벨만 강조. 제외 수/사유는 유지 |
| 사용자가 건너뛰려 함 | 임의 재생 seek 기능은 현재 없음 | 최초 단계에서 seek를 새로 약속하지 않음. 나중에 넣으면 이전 음 off/계획 종료 확인 후 새 묶음으로 시작하며 취소 뒤 옛 사건을 무시해야 함 |
| N/P·마우스 선택 | 확인 필요/편집 탐색 기능 | 재생 seek 단축키로 바꾸지 않음. 선택 강조와 현재 연주 강조를 분리 |
| 창 닫기 | 현재 cancel 후 destroy, worker finally에서 장치 정리 | `after` 예약과 오버레이 상태도 정리. 닫힌 위젯에 worker 사건을 적용하지 않음 |

빠른 중지→쪽 전환→다시 시작 때 옛 worker의 start/end/finished가 늦게 도착할 수 있다. 재생마다 token과 대상 쪽/session·문서 revision을 고정하고 현재 token/revision과 다른 사건은 버린다. 메인 중지 시 즉시 토큰을 무효화하고 강조를 지우며, 실제 note-off/reset/close는 worker finally가 수행한다. 메인 스레드에서 긴 join으로 UI를 멈추지 않는다.

「확인 필요 제외」를 재생 도중 바꾸면 다음 시작부터 반영한다고 명시하거나 변경 시 중지하는 한 정책을 정해야 한다. 반영 도중 그룹 목록을 조용히 바꾸지 않는다. 이후 리듬 단계에서 제외 음의 원래 시간을 어떻게 유지할지는 별도 시간/쉼표 계약으로 협의한다.

## 5. 사용자 수정·구간 조표·겹임시표 일치 검증안

이번에는 아래 검사를 **실행하지 않았다**. 기대값은 읽은 기존 검사/설계의 회귀 사례이며 새 실악보 통과 결과가 아니다.

| 항목 | 고정할 사례와 기대 | 검증할 일치 |
|---|---|---|
| 조표/제자리표 | B3 + 쪽 B♭ → MIDI58, natural →59 | 화면 라벨·계산된 MIDI·켠 건반·전송 note-on이 같음 |
| 사용자 수정 우선 | 기존 B3 라벨을 고정도 「도#」로 수정하면49, 「시#」면60 | 저장 원음고/accidental/확신도/flags는 보존하고 edited 표기의 소리를 우선. 기존 옥타브 정책도 그대로 유지 |
| 구간 조표 우선 | #387 사례 D5/「레b」/라벨 key에 D♭가 있으면73, 쪽 기준 D면74 | 건반도 label.key가 우선한 pitch_to_midi 값을 사용. 쪽 key로 다시 계산하지 않음 |
| 겹임시표 | #391 사례 D4bb→60, F4##→67, B4##→73, C4bb→58 | 자연음 기준±2이며 조표에 추가로 더하지 않음. 표시 레bb/파##와 건반 C/G 등의 이명동음 차이를 오류로 처리하지 않음 |
| 이동도 수정+구간 조표+겹임시표 원값 | #391 최신 사례 D5bb/edited「도」, label.key 으뜸음Db →73 | 이전 쪽 으뜸음 C로 잘못 바뀌지 않으며 원래 bb/check/이력 보존 |
| check/주의/확인한 수정 | 일반 check 제외, caution 유지, edited check는 재생 | MIDI가 같은 제외 라벨이 있어도 재생에 포함된 라벨만 강조. check를 재생했다고 certain으로 저장하지 않음 |
| 종류 불명 | double_acc flag만 있고 bb/## 값이 없을 때 | 건반 기능이 종류를 추측하지 않음. 현행 유효값/제외 정책 유지 |
| 같은 음 중복/이명동음 | 같은 x·MIDI에 서로 다른 라벨/이명 표기 | 소리/건반은 하나, 포함된 모든 라벨 강조. 중복 id/좌표도 한 개로 잃지 않음 |
| 좌표/성부 가정 | 같은 시스템의 정확한 x 일치 vs 아주 가까운 서로 다른 x, 다음 시스템에서 x 재시작 | 현재 묶음·순서를 그대로 보존. 인식의 위치 변화로 진짜 동시음을 보장한다고 주장하지 않음 |
| 추가/삭제/되돌리기/다시 열기 | 표시되는 현재 쪽의 최신 수정본/영역 doc | 삭제 음은 계획에서 빠지고 추가 음·undo가 반영. 재열기 전후 pitch_to_midi와 계획/강조 대응이 같음 |
| 범위/오류 | 유효 MIDI10/127은 88건반 밖, 128 등 잘못된 값은 거부 | 표시 바깥 음을 조용히 자르지 않음. 장치 부재/부분 note-on 실패/정리 실패/빈 계획에서 강조가 남지 않음 |

### 알려진 한계를 다른 기능에서 고친 것으로 쓰지 않기

- 조사 당시 main718abd3에는 typed bb/## 소비가 없었지만 #388/#391 연결은 이후 병합됐다. e141908은 레bb/파## 표기와 자연음 기준±2 계약을 포함하며 #401에서 frozen 수치 검사를 통과했다. 실제 GUI 개별음 루프백은 미확인이며 건반 기능의 검증으로 쓰지 않는다.
- #387 기록상 `user_created` 라벨은 구간 key가 없어 조바꿈 뒤 이동도 수정 재생에 쪽 으뜸음이 쓰일 수 있다. 건반이 같은 잘못된 소리와 일치한다고 이 문제가 해결된 것은 아니다. 구간 문맥을 근처 라벨에서 임의 추정해 넣지 말고 CLI 협의 사항으로 남긴다.
- label_edits는 수정 문구를 수용하더라도 재생층이 해석 못 하는 문자열은 제외한다. 임의 문구를 기본 음으로 조용히 되돌리는 동작을 건반에도 넣지 않는다.

## 6. 이후 구현 검증 순서와 완료 기준

1. 데이터층: 현재 audio_groups 결과/제외 사유와 새 계획의 MIDI/순서가 같고, 원문 doc 및 파일 바이트가 불변인지 검사한다. `pitch_to_midi`를 시험 대상과 별개 정답으로만 재사용하지 말고 위의 명시한 기대 MIDI·정답 악보 사례와도 대조한다.
2. 장치 경계: 기존 WinMM mock 검사에 묶음 시작/끝 순서와 부분 실패·중지·callback 오류 시 note-off/reset/close 보장을 추가한다. 실제 청취/오디오 지연 검증과 구분한다.
3. GUI: token/revision과 사건 queue를 통제해 묶음의 라벨/건반이 같은 상태가 되는지, 중지/전환 뒤 늦은 사건·중복 MIDI·확대/스크롤·편집 선택/N/P 간섭·닫힌 창/타이머 누수를 확인한다. 키 강조만 바뀔 때 전체 미리보기 이미지를 매번 리사이즈하지 않는지도 확인한다.
4. 독립 실제 입력: 개발 fixture와 별도로 사용자 수정·구간 조표·겹임시표가 있는 실악보에서 표기/선택/저장재열기/재생 note와 건반을 대조한다. 실제 exe/루프백 관측을 남기고 장치 명령 성공만으로 스피커 청취를 통과 처리하지 않는다.
5. 회귀: Aoharu1·D♭1·Bach1 기본 PNG/JSON6파일 바이트0, 골든711/PDF17 유지와 전체 검사 실패0·건너뜀0. 재생 전/중/후 및 저장 결과 파일도 바이트 불변이어야 한다. 재생 오버레이는 화면 상태이고 renderer 출력에 넣지 않는다.

새 UI의 88건반 가독성, 실제 드라이버/Tk 지연, 실제 청취는 아직 미확인이다. 리듬·쉼표·타이·박자 기반 seek 및 양손/성부 판별은 다음 단계 계약이며 이번에 자동으로 해결되지 않는다. 구현 API·패널 크기·강조 색/윤곽은 아직 채택하지 않았다. e141908 베타 보고 뒤 사용자 지시로 이 초안을 문서 PR로 올린다. 리듬 시간축은 #396과 협의하고 구현은 별도 승인/검증 단계다.
