# PR #50 검증 — 검증 악보의 폰트는 무엇이고 템플릿이 맞는가 (2026-09-18)

> **결론 셋.**
> 1. **쇼팽·바흐 PDF는 전부 Emmentaler다.** LilyPond 조판이고, 옛 판본(2.12)까지 템플릿과 IoU 0.93~0.98로 맞는다.
>    → **임시표 수정 착수를 막는 폰트 문제는 없다.**
> 2. **단 대조군 20개가 전부 큰 광학 크기(18~20호)다.** 같은 Emmentaler라도 작은 크기(11~14호)는 IoU 0.73~0.88로 어긋난다.
> 3. **비-Emmentaler 표본(RE:Aoharu)에서는 템플릿이 안 맞는다** — 불일치율이 오류 집단과 겹친다. 해상도 탓이 아니다.
>
> 측정: `modules/` 무변경 · PR #50 도구 그대로 재실행 + 폰트 윤곽 직접 추출

---

## 1. 어떻게 확인했나 — 메타데이터와 형태 둘 다

**(a) 메타데이터** — PDF에 내장된 폰트 이름을 직접 읽었다(PyMuPDF `get_fonts`).

| 악보 | 생성기 | 내장 음악 폰트 |
|---|---|---|
| 바흐 미뉴에트 | LilyPond **2.12.1** | Emmentaler-20 · Emmentaler-26 · feta-alphabet20 |
| 쇼팽 B♭m | LilyPond (버전 없음) | **PFAEmmentaler**-14 · -20 |
| 쇼팽 D♭ | LilyPond **2.14.2** | Emmentaler-11 · -13 · -14 · -16 · -18 · Brace |
| 쇼팽 Em | LilyPond **2.18.2** | Emmentaler-11 · -13 · -18 · -20 · Brace |
| 픽스처(빔·조표·온음표) | LilyPond **2.26.0** | Emmentaler-20 · Brace |

**네 악보 모두 Emmentaler 계열이다.** Mutopia 악보라 LilyPond 조판이고, 상용 출판사 조판(Finale Maestro·Sibelius Opus·Dorico Bravura)은 **하나도 없다.**

**(b) 형태** — 메타데이터 이름만 믿지 않고, 각 PDF에 박힌 CFF 글리프 윤곽을 뽑아
템플릿 출처(바흐 Emmentaler-20)와 **높이를 맞춰 겹쳐** 보았다(IoU).

| 폰트 (쓰는 악보) | ♯ | ♮ | ♭ |
|---|---:|---:|---:|
| Emmentaler-20 (바흐 = 템플릿) | 1.000 | 1.000 | 1.000 |
| **PFAEmmentaler-20 (B♭m, 가장 오래된 판본)** | **0.935** | **0.974** | **0.978** |
| Emmentaler-18 (D♭·Em) | 0.960 | 0.967 | 0.956 |
| Emmentaler-14 (D♭) | — | 0.884 | — |
| Emmentaler-13 (D♭) | — | 0.835 | 0.801 |
| **Emmentaler-11 (D♭·Em)** | **0.837** | **0.794** | **0.729** |

**LilyPond 버전 차이는 작다**(2.12 → 2.26에서 0.93~0.98). **벌어지는 것은 광학 크기다** —
작은 음표용 11~14호는 획이 상대적으로 두꺼워 같은 이름이라도 모양이 다르다.

B♭m은 **옛 글리프 이름**을 쓴다(`accidentals.2`=♯ · `.0`=♮ · `.M2`=♭). #50 도구는
`accidentals.`/`noteheads.` 접두사로 받으므로 영향이 없다.

## 2. 대조군 20개 — 선정은 검출 결과와 독립이고 빠짐이 없다

PDF 글리프 위치로 선정 영역의 임시표를 전부 뽑아 명세와 대조했다(조표 제외).

| 영역 | 조표 밖 임시표 | 대조군에 든 것 |
|---|---:|---:|
| B♭m 1쪽 첫 시스템 | 5 | **5** |
| D♭ 1쪽 둘째 시스템 | 3 | **3** |
| Em 1쪽 첫 두 시스템 | 12 | **12** |

**골라낸 흔적이 없다.** 영역 안의 것을 전부 넣었다. 검출 결과를 보고 고른 것이 아니라는 Codex의 기술과 맞는다.

**다만 크기가 한쪽이다.** 대조군 20개의 글리프 크기는 **전부 18.6~20pt(Emmentaler-18·20)**이고,
위 표에서 어긋나는 **작은 크기(11~14호)는 대조군에 하나도 없다.** #50이 적은 「작은 ♮ 측정 불가」는
**표본이 큰 크기에만 있다**는 뜻이기도 하다.

## 3. 분포 재현 — 수치 2562개 전부 일치

PR #50 도구를 그대로 다시 돌려 커밋된 결과 JSON과 대조했다.

- `missing_fraction` · `unexplained_fraction` · 거리 · 겹침 · 정합 위치 **2562개 값 불일치 0**
- `module_sha256`은 같다. **`tool_sha256`·`manifest_sha256`은 커밋된 결과에 적힌 값과 다르다** —
  결과 JSON이 지금 PR에 든 도구·명세 파일과 **다른 판본에서 생성**됐다는 뜻이다. 수치가 같으므로 내용 차이는 아니지만,
  원자료의 출처 표기로는 어긋난다

## 4. 비-Emmentaler에서는 맞지 않는다

검증 자료 중 Emmentaler가 아닌 것은 **RE:Aoharu 화면 캡처 한 장**뿐이다(2026-09-28 정정: 「LilyPond가 아닌」 → 확인된 것은 글리프가 Emmentaler와 안 맞는다는 것까지이고, 조판 프로그램은 모른다). 임시표가 없어 **조표 ♯ 21개**에
같은 템플릿을 같은 방식으로 정합했다. 해상도 차이(sp 11.6 대 20.8)를 가르려고 **바흐를 같은 sp로 축소한 대조**를 함께 쟀다.

| 대상 | 모델 픽셀 불일치율 | 평균 최근접 거리(sp) |
|---|---:|---:|
| 바흐 원본 ♯ (sp 20.8) | 0.047 | 0.0022 |
| **바흐를 sp 11.6으로 축소** (해상도 대조) | **0.081** | 0.0070 |
| **RE:Aoharu 조표 ♯ 21개** | **0.154~0.554** (중앙 0.220) | 0.0145~0.0895 |
| [참조] #50 정상 ♯ 11개 | 0.026~0.066 | 0.0031~0.0053 |
| [참조] #50 직접 오류 9건 | 0.333~0.640 | 0.0415~0.1149 |

**해상도만으로는 0.081까지다. Aoharu는 중앙 0.220이고 최대 0.554로 오류 집단(0.333~0.640)과 겹친다.**
즉 **다른 조판에서는 이 템플릿이 정상 기호도 「오류」로 읽는다.**

## 5. 그래서 무엇을 할 수 있나

- **지금 검증 악보(전부 Emmentaler)에 대해서는 템플릿 접근이 성립한다.** 임시표 오삭제 수정을 이 근거로 진행해도 된다
- **일반화 주장은 못 한다** — 상용 조판 폰트 표본이 0개이고, 유일한 비-Emmentaler 표본에서 분리가 무너진다
- **같은 Emmentaler 안에서도 작은 광학 크기는 미검증이다** — 대조군이 전부 큰 크기다. 꾸밈음·작은 보표의 임시표는 별도 표본이 필요하다
- 앱(촬영 입력)으로 가면 폰트를 고를 수 없다. **제품 조건으로 채택하려면 다른 폰트 계열 표본이 선결**이다
