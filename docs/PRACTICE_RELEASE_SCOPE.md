# 첫 GitHub 공개 배포 — 본격 연습 버전 목표·범위 초안

## 사용자 결정 (2026-10-18)

사용자는 지인용 베타보다 넓은 GitHub 공개 배포를 원하며, 「본격 연습 버전까진 만들고 배포하고 싶어」라고 결정했다. 단순 음높이 확인 단계에서 공개를 마치는 대신, 박자에 맞춰 듣고 구간을 반복하며 속도를 조절하는 연습 기능까지 준비한다.

이 문서는 그 결정과 Codex의 최소 범위 제안을 구분해 보존한다. 아래 세부 지원 범위·수치·인터페이스는 아직 확정된 구현 설계가 아니며, 기존 파일 소유권과 판정 변경 절차를 바꾸지 않는다. Soundslice 전체 기능 구현이나 공개 배포 실행을 승인한 기록으로 쓰지 않는다.

## 10-18 후속 사용자 결정 — 착수 순서

사용자는 현재 작업을 마무리한 뒤 위 연습 기능들을 추가하고, 다른 AI에도 이 순서를 공유하도록 지시했다. 먼저 #388·#391 실제 연결·실악보 독립 검증·병합/내부 베타 절차를 마무리한다. 그 뒤 계이름 배치 → 건반/재생 위치 → 리듬/본격 연습 → 공개 배포 검증 순서로 진행한다. 내부 검증용 빌드와 GitHub 공개 배포를 구분한다.

#388/#391 연결은 13d73f6으로 병합됐고 사용자 승인 #394의 D♭ selftest 기준 갱신 병합 e141908로 내부 베타를 한 번 만들었다. 빌드 검증·실제 입력 결과와 미확인은 [#401 기록](releases/e141908/PREFLIGHT.md)에 있다. 이는 공개 배포 완료가 아니며 배치/건반/리듬 구현도 아니다.

공유 인계: https://github.com/tkcjsrn1/sheet-music-helper/pull/388#issuecomment-6248752875

## 첫 공개에 제안하는 필수 기능

| 단계 | 사용자가 할 수 있어야 하는 일 | 완료 근거 |
|---|---|---|
| 1. 읽기 | 일관된 위치의 계이름을 읽고, 화음의 각 라벨을 구분한다 | 원본 음표·임시표 가림, 라벨 간 겹침, 음표와 라벨 연결 혼동을 여러 악보/해상도에서 비교 |
| 2. 확인 | 음표 선택과 재생에 맞춰 해당 라벨·건반을 보고, 틀린 음을 수정한다 | 사용자 수정·겹임시표·구간 조표를 포함해 화면, 저장 JSON, 실제 재생 음높이가 일치 |
| 3. 연습 | 음 길이·쉼표·동시음을 반영해 듣고, 구간 반복과 속도 조절을 한다 | 소스 정답이 있는 악보의 시작 시각·길이·화음 동시성·반복 경계를 각각 대조 |
| 4. 이어 하기 | 여러 쪽을 넘기고 수정·연습 상태를 저장한 뒤 다시 연다 | 저장/재열기 후 사용자 수정과 선택 쪽 보존, 실패 시 원본/수정 기록 무손실 |
| 5. 배포 | 개발 도구 없는 Windows에서 열고, 결과 저장과 신고 ZIP 생성을 한다 | 빌드 기준 커밋, 소스/exe 비교, selftest, Defender, Actions, 실제 사용자 환경 결과 기록 |

메트로놈과 재생 위치 강조는 3단계의 시간 정보와 같은 기준을 사용한다. 현재의 음높이 미리 듣기와 박자 있는 곡 재생을 UI에서 구분한다.

## 가장 먼저 할 일 — 계이름 배치

사용자가 제시한 문제: 계이름 위치가 음표마다 조금씩 달라 읽기 어렵다. 참고: https://www.soundslice.com/help/en/player/advanced/226/showing-pitch-names/

현재 renderer는 잉크와 다른 라벨을 피하려고 개별 라벨의 상하 방향·가로 위치·거리까지 바꾼다. 렌더링 개선에서는 같은 상황의 배치 방향·간격을 통일하고 화음을 묶어 정렬하는 대안을 실제 악보 전후 그림으로 비교한다. 특정 방향이나 간격 상수는 아직 채택하지 않는다. 기존 배치 상수의 측정 절차를 지키고, 정돈됐다는 이유만으로 음표 가림이나 라벨 뒤바뀜을 허용하지 않는다.

이 변경은 PNG의 위치가 의도적으로 달라지는 작업이다. 인식된 음표 수·좌표·음고·임시표·확신도와 원본 라벨 데이터는 유지해야 한다. GUI만 바꾸는 작업의 「기본 PNG 바이트 변화 0」 조건과 혼동하지 않는다.

## 리듬 단계 착수 전 확정할 것

- 음 길이, 쉼표, 성부, 화음의 시작 시각, 박자표, 붙임줄, 잇단음표, 반복 기호 중 첫 지원 범위를 정한다. x 좌표 간격을 실제 연주 시간으로 대신하지 않는다.
- 지원하는 악보 유형과 판독 불가를 알리는 방법을 정하고, 구현에 쓰지 않은 별도 검증 악보를 확보한다.
- 구조화한 시간 정보의 정답은 원본 소스에서 얻고 음표마다 시작·길이·음고를 따로 대조한다. 최종 라벨 수가 같은 것으로 리듬 정답을 대신하지 않는다.
- 시간 정보를 확정하지 못한 구간은 이유를 알리고 본격 연습 재생을 제한한다. 임의의 일정 간격 재생을 정상 곡 재생으로 표시하지 않는다.
- 현재 modules/label_audio.py와 docs/D2_PITCH_AUDIO.md는 같은 x 묶음/고정 길이 재생을 명시하며, docs/LABELS_SCHEMA.md도 리듬을 미구현으로 적고 있다. duration 하나만 추가해 성부·동시성까지 해결된 것으로 간주하지 않는다.
- 인식·판정과 JSON 스키마는 Claude 담당이다. #388·#391의 조건부 schema 2 및 구간 조표·사용자 수정 이력을 보존하는 호환 계약을 먼저 확인하고, Codex가 독자적으로 기존 판정 파일이나 골든을 바꾸지 않는다.

## 배포 전 통과 기준 제안

- 공개용 저장소 정리(이력에 악보 이미지 약 620개): 사용자 전달 수치이며 이 문서 작업에서 재집계하지 않았다. 공개 전에 현재 파일뿐 아니라 Git 이력의 악보 이미지·출처·공개 허용 여부와 포함할 검증 자료를 점검하고 공개용 구성을 확정한다. 이 조건을 적는 작업에서 이력 재작성·force push·원본 삭제는 하지 않는다.
- 정답 골든 711 불변. PDF17은 정답이 아닌 변화 감지 자료로 다루고, 변경 행을 구분해 검토한다.
- 새 오삭제 0. 라벨 추가·삭제·표기·확신도 변경을 각각 보고한다.
- 알려진 약점을 문서에 남기고, 새 악보에서 경고 없이 틀린 결과와 확인 요청량을 따로 측정한다.
- 사용자 수정, 조바꿈, 겹임시표를 반영한 표기·재생·저장/재열기 일치.
- run_all 실패 0·건너뜀 0과 기존 배포 검증을 완료한다. 새 리듬/배치의 정확성은 별도 정답 대조와 화면 확인으로 검증한다.
- 스피커 청취·실제 다운로드 SmartScreen 등 사람이 확인하지 않은 항목을 통과로 적지 않는다.

## 별도 후속 제안

화면 폭에 맞춘 악보 재조판, 악보 전체 조옮김, 연주 영상 동기화, 다양한 악기의 운지 표시는 첫 공개 필수 범위에서 제외하는 안을 제안한다. 사용자가 아직 이 세부 경계를 승인한 것은 아니다.

핵심 연습 기능 2~4개월이라는 대화의 추정은 작업량 추정이며 확정 일정이 아니다. 리듬 인식의 지원 범위와 독립 검증 결과를 얻은 뒤 다시 산정한다. 첫 공개 전 내부 검증용 베타를 만드는 것은 계속 가능하지만, 사용자 결정 없이 공개 배포하지 않는다.

## 현재 상태와 다음 단계

- 범위만 기록했다. 리듬 기능·새 배치·건반 UI 구현 및 검증은 아직 시작하지 않았다.
- #388/#391 연결 베타 검증 보고는 #401로 마쳤다. #397은 미병합이며 그 selftest 5행은 이번 문서에서 변경하지 않는다. 이 문서는 다음 빌드 신호가 아니다.
- 다음 작업: 계이름 배치의 실제 전후 비교안을 먼저 만들고, 별도로 리듬 입력/정답/소유권 계약을 Claude와 합의한다. 종합 구현 계획은 지원 범위를 확정한 뒤 단계별로 작성한다.
