# D-3 결과 라벨 수정 UI 설계안

상태: **데이터층 병합. 사용자 요청으로 GUI 1차(표시 글씨 수정·삭제·되돌리기)를 구현해 검토 중. 추가·재인식 이월은 후속.** 현재 JSON 스키마와 GUI 코드를 기준으로 했다.

## 사용자 흐름

1. 변환 결과를 연 뒤 주황 점선(`check`) 라벨을 우선 확인한다. 라벨 글씨를 누르면 음이름을 바꾸거나 삭제할 수 있다. 변경 직후 미리보기와 JSON을 함께 갱신한다.
2. 빈 자리를 누르면 그 지점에 라벨을 추가한다. 먼저 보표·음고·표기 문자열을 확인받는다. 보표나 음고를 자동 추측해 조용히 저장하지 않는다.
3. 원본을 다시 인식할 때 사용자 수정이 자동 판정을 이긴다. 옮길 대상을 찾지 못하면 조용히 버리지 않고 별도 목록으로 보여준다.

## 클릭 위치와 화면 상태

- 음표 중심 좌표(`labels[].x/y`)를 라벨 클릭 대상으로 쓰지 않는다. 렌더러는 겹침을 피해 글씨를 옮긴다. `render_solfege_on_image()`의 반환 `placements`에 실제 `x/y/w/h`와 `note`가 있으므로, 이 상자를 현재 미리보기 세션에 보관한다.
- 캔버스 클릭을 `canvasx(event.x)/zoom`, `canvasy(event.y)/zoom`으로 원본 이미지 좌표에 되돌려 상자 포함 여부를 검사한다. 확대·축소와 스크롤 뒤에도 동일한 라벨을 선택해야 한다. 상자가 겹치면 후보를 목록으로 보여주고 사용자가 고른다.
- 상자는 **화면 선택용 임시 정보**다. 저장된 라벨 문서에는 넣지 않는다. 글꼴·크기·배치가 바뀌면 다시 렌더링해 상자도 새로 받는다.
- 처음에는 `check` 라벨의 삭제·문자 수정에 초점을 맞추되, 같은 조작으로 `certain`·`caution`도 고칠 수 있게 한다. 키보드로 라벨 목록을 이동하고 선택·삭제하는 경로도 마련한다.

## 데이터와 저장

- 기존 스키마 1의 라벨에는 `text`, `pitch`, `staff`, `x/y`, `confidence`, `flags`, `edited`가 있다. 문자열만 고칠 때는 `text`를 바꾸고 `edited: true`로 저장한다. 음고를 바꿀 때는 `pitch`·`step`·`accidental`의 관계를 함께 검증해야 하므로 별도 입력 단계가 필요하다.
- **삭제는 단순히 배열에서 빼면 재인식 때 복원된다.** `edited: true`인 삭제 기록(tombstone)을 남기고 재렌더러가 그 라벨을 건너뛰는 데이터층 변경이 필요하다.
- 추가 라벨은 `edited: true`와 사용자 생성 출처, 보표·좌표·음고·표기를 갖는다. 기존 `label_id`는 매칭 키가 아니므로 중복 식별 문제를 별도로 정해야 한다. 빈 자리 클릭만으로 `pitch`를 확정할 수 없다.
- 현재 `carry_over_edits()`는 기존 라벨의 **text만** 옮긴다. 삭제·추가·음고 수정 보존은 지원하지 않는다. `modules/labels_io.py`는 Claude 소유이므로 스키마와 재인식 규칙은 먼저 합의받아야 한다. 골든 TSV는 건드리지 않는다.
- 원본 해시·페이지·이미지 크기·DPI 검사는 기존 `check_source()`/`check_dpi()`를 그대로 따른다. JSON은 임시 파일에 쓴 뒤 교체하고, 실패하면 기존 JSON·PNG를 보존한다. 원본 인식 결과와 사용자 수정본을 구분할 수 있게 저장한다.

### 데이터층 (GUI 연결 전)

`modules/label_edits.py`는 원본 라벨 JSON을 바꾸지 않고 별도 수정 기록을 적용한다. 수정 파일에는 원본의 SHA-256·쪽·이미지 크기와 `changes` 목록을 둔다. `set_text`·`delete`는 이전 라벨의 보표·좌표·음고·표기를 함께 기록하고, `add`는 사용자가 지정한 보표·좌표·음고·표기를 기록한다. 삭제 기록은 이 별도 파일에 남고, 적용 결과의 라벨 목록에서는 빠진다. 대상이 없거나 둘 이상이면 적용을 거부한다. 새 라벨은 `edited: true`, `user_created: true`로 표시한다.

2026-10-02 사용자 승인으로 별도 파일 방식의 데이터층을 채택했다. **같은 원본의 같은 쪽**에만 적용하며, 재인식한 결과로의 이월과 GUI 연결은 아직 하지 않는다. 미매칭 수정의 사용자 화면은 결정이 필요하다.

## 재렌더링과 검증

- 수정 뒤 `document_notes()`와 `render_solfege_on_image()`로 원본 위에 다시 그린다. 편집은 음표 검출·조표 판정을 다시 실행하지 않는다. GUI는 선택과 입력만 담당하고 수정·삭제·추가·재인식 이월은 데이터층 API로 둔다.
- 검사: 점선 라벨 선택, 확대/스크롤 뒤 같은 선택, 화음 근접 상자, 텍스트 수정·삭제·추가 후 JSON 저장과 재실행, 원본 불일치 거부, 재인식 후 수정 보존과 미매칭 알림. 각 변경 뒤 골든 711개와 전체 인식 결과는 불변이어야 한다.

## 사용자 확인이 필요한 결정

1. 삭제 기록과 사용자 추가 라벨을 스키마 1의 선택 필드로 넣을지, 스키마 버전을 올릴지.
2. 음이름만 고칠 때 `pitch`도 함께 바꿀지. 화면 표기만 바꾸면 다른 표기법으로 전환할 때 의미가 달라질 수 있다.
3. 사용자가 추가한 라벨이 재인식 때 겹치면 자동 병합하지 말고 어떤 선택 화면을 보여줄지.


## GUI 1차 (2026-10-03, PR #153 판정 반영)

현재 쪽의 렌더러 배치 상자를 써서 글씨 수정·삭제·되돌리기를 연결한다. 겹친 상자는 임의 선택하지 않고 목록에서 고른다. 키보드 목록 선택·Enter로 입력·Delete로 삭제·Ctrl+Z로 취소를 지원한다. 원래 인식 결과는 덮어쓰지 않고 수정본 PNG·라벨 JSON·삭제를 포함한 별도 수정 기록을 새 폴더에 함께 저장한다. 글씨만 고치므로 음고와 조표는 그대로다. 자세한 범위·실제 화면·검증은 [검토 기록](review/label_edit/README.md)을 참조한다.

빈 자리 추가와 수정 파일 다시 불러오기, 새 인식 결과로 이월은 이번 범위에서 제외했다. 여러 쪽 처리는 기존 첫 성공 쪽 미리보기만 편집한다. Claude 기능 판정 통과 후 사용자 수정 라벨은 점선 없이 확실 라벨과 같은 진한 글씨로 그린다. 원래 확신도와 이전 표기는 라벨 JSON·수정 기록에 보존하며, 삭제한 라벨은 그림에서 완전히 뺀다. GUI 저장과 CLI 재렌더링이 같은 그리기용 확신도 함수를 쓴다. 확대/스크롤한 실제 캔버스 클릭 이벤트로 대상 선택을 확인했다.


## GUI 2차: 빈 자리 추가·연속 되돌리기 (2026-10-03)

이미 그린 글씨 상자는 기존 직접 클릭 선택을 쓰고, 이미지 안의 빈 자리는 추가 창을 연다. 사용자가 보표 번호·음고(C4, B3 등)·표기를 직접 입력한다. 좌표로 음고나 보표를 자동 확정하지 않는다. 이미지 밖 클릭, 보표 미선택, 잘못된 음고, 같은 보표/좌표의 중복은 추가하지 않는다. 기존 데이터층 add와 같은 원본 검사·저장 실패 보존을 적용한다.

추가된 라벨은 `edited: true`, `user_created: true`와 사용자 수정 기록을 남기며 진한 글씨로 그린다. 수정·추가·삭제를 섞어 여러 번 되돌릴 수 있고 마지막 취소는 원본 PNG/JSON 경로와 바이트로 돌아간다. 마지막 라벨 삭제 시 목록을 먼저 갱신해 미리보기의 이전 선택 번호가 남지 않게 했다. 인식과 기본 변환 경로는 그대로다. 수정 파일 다시 불러오기와 재인식 이월은 후속이다.
