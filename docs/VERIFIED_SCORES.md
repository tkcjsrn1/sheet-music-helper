# 검증한 악보 — 무엇을 어디까지 확인했나

**새 악보가 들어왔을 때 "이건 검증된 조건인가"를 여기서 바로 본다.**
지금까지 여러 문서에 흩어져 있던 것을 한 표로 모았다. 개발용 문서다
(사용자용은 `docs/STATUS.md`).

**「확인 방법」이 이 표의 핵심이다.** 같은 "오류 0"이라도 전수 판정과 관찰만은
무게가 전혀 다르다. **확인 방법을 안 보고 숫자만 읽으면 안 된다.**

---

## 확인 방법의 뜻

| 표기 | 뜻 |
|---|---|
| **전수 판정** | 라벨을 **하나도 빠짐없이** 사람이 원본과 대조했다. 가장 무겁다 |
| **골든 고정** | 전수 판정한 결과를 파일로 박아 두고 **매 커밋마다 기계가 대조**한다. 한 글자만 달라져도 실패한다 |
| **표본 판정** | 일부를 뽑아 사람이 판정했다. 나머지는 모른다 |
| **관찰만** | 돌려서 결과를 보기만 했다. **정답과 대조하지 않았다** |
| **전처리만** | 오선을 찾는 데까지만 확인했다. 계이름은 안 봤다 |
| **소스 대조** | **합성 악보**의 생성 소스(LilyPond `.ly`)에서 정답을 얻어 **기계가** 대조한다.
  사람 비용이 0이고 **음표→라벨 방향**이라 오삭제를 잡는다. 대신 **그 조판만** 덮는다 |

### 전수 판정의 한계 — **오삭제를 못 잡는다** (2026-09-08 추가)

**전수 판정은 「출력된 라벨」을 원본과 대조하는 방식이다.** 라벨 하나하나에 대해
"이 자리에 이 음표가 맞나"를 본다. 그러니 **지워진 음표는 애초에 대조 대상에 없다** —
라벨이 없으니 검사할 것도 없다.

> **아래 표에서 확인된 오류가 전부 「없는 음이 하나 더」인 것은
> 방법의 결과이지 오삭제가 없다는 뜻이 아니다.**

기계 쪽도 같은 구멍이 있다. `verify.reverse_check`는 이름과 달리 **라벨을 돌며
잉크를 확인**한다. **「음표가 있는데 라벨이 없나」를 보는 검사는 코드에 없다.**

**실제로 놓치고 있었다.** 조표 픽스처 15종의 LilyPond 소스에서 정답 음표 수를 세어
대조하니(`tools/count_fixture_notes.py`) **11종에서 18개가 부족**했다. 그 픽스처들은
임시표가 0개라 임시표 결함과도 무관한, **지금까지 한 번도 안 보이던 손실**이다.
`docs/ACCIDENTAL_GHOST_MEASURE.md`에서 확인한 오삭제 7건도 같은 구멍에 있었다.

**검사는 양방향이어야 한다.** 확대안은 `docs/GOLDEN_EXPANSION.md`.

### 조표 픽스처 15종 — **정답 168개 중 18개가 빠진다** (2026-09-08)

같은 선율을 15개 조로 이조한 LilyPond 합성 악보다. **소스에 선율이 그대로 있어
정답이 168개**(오른손 108 · 왼손 60)로 확정된다. 화음이 없어 **음표 하나 = 라벨 하나**다.

| | 결과 |
|---|---|
| 15종 중 **11종이 음표를 놓친다** | 부족 합계 **18개** |
| 1종은 하나 더 많다 | `14_Gb_major_flat6` (+1, 덧줄 위 이중 검출 +3 / 다른 자리 −2) |
| **18개가 전부 같은 유형** | 각 8마디 블록 끝의 **온음표 `c1`** |

**조표와 무관하다.** 경로는 둘이다 — 검출 실패 7개(링이 타원 opening에 깎여 좌우

### 아직 한 번도 검증하지 않은 조건

**여기 있는 것이 다음에 확보할 테스트 악보의 우선순위다.**

| 항목 | 검증한 것 | **한 번도 안 본 것** |
|---|---|---|
| 조표 | ♯2 · 없음 · ♭5 (실제 악보) / **♯1~♯7 · ♭1~♭7 (합성, 소스 대조)** | **♯1·♯3~7·♭1~4를 실제 악보로 본 적은 없다** |
| 단수 | 피아노 2단 | **1단(성악·독주), 3단 이상** |
| 입력 | 인쇄 PDF · 화면 캡처 | **사진 촬영본** |

**`♯1`(사장조)과 `♭1`(바장조)이 특히 급하다** — 초·중급 악보에 가장 흔한 조표인데
**한 번도 안 봤다.** 조표 개수를 세는 코드는 "모든 보표에서 같은 x에 있는 세로 막대를
교차 투표"하는 방식이라, **막대가 하나뿐일 때 표가 갈리는지 아직 모른다.**

`♭5`(쇼팽)와 `♯2`(RE:Aoharu)만 봤다는 것은 **막대가 여러 개인 경우만 봤다**는 뜻이다.

## 새 악보가 들어왔을 때

1. **1번 표의 조건과 비교한다** — 조표 개수, 단수, 인쇄인지 스캔인지
2. **위 4·5번에 걸리는 특징이 있는지 본다** — 3단, 곡 중간 조바꿈, 오래된 스캔,
   곡 중간 조표·음자리표
3. **줄 수를 눈으로 세어 결과와 맞춰 본다.** 이것이 가장 빠른 실패 감지다
4. 정답을 판정할 만한 악보라면 **전수 판정 후 골든에 넣는다** — 그래야 회귀가 잡힌다

**"돌아갔다"와 "맞다"는 다르다.** 사티는 예외 없이 끝났지만 8줄 중 1줄만 찾았다.
완료 메시지로 품질을 판단할 수 없다.
