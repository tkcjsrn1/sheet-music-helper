# PDF 17쪽 「변화 감지용 스냅샷」 (2026-09-30, TASKS [1] · 사용자 승인)

## 정답 골든과 무엇이 다른가

| | 아오하루 정답 골든 | **PDF 변화 감지용 스냅샷** |
|---|---|---|
| 파일 | `tests/golden/aoharu_*.tsv` (라벨 711) | `tests/golden/snapshot_pdf_*.tsv` (34개: 라벨 5,151줄 + 보표 문맥) |
| 내용 | **육안 전수 대조로 정답이 확인된 값** | 검증 PDF 17쪽(바흐 1 · B♭m 6 · D♭ 6 · Em 4)의 **제품 출력 그대로** — 정답 아님 |
| 알려진 오류 | 없음 | **있다**: 임시표 뒤바뀜 · 가짜 임시표와 그 전파(A-17), 임시표 글리프 · 빔 위 유령 라벨(20쪽 90여 개), 붙은 화음 누락 등 |
| 바뀌면 | **퇴행** — 실패. 정답이 바뀌는 변경은 승인 대상(CLAUDE.md §5) | **판정 대상** — 오류가 아니다. 인식이 좋아져도 바뀐다 |
| 갱신 | `--update` (승인 뒤) | `--update-snapshot` (바뀐 줄 육안 판정 뒤) |

둘은 갱신 옵션이 따로다 — 스냅샷을 갱신하면서 정답 골든을 실수로 덮지 않는다.

## 스냅샷이 바뀌었을 때 절차

`test_golden_regression.py`는 스냅샷이 바뀌면 `[판정 필요]`를 찍고 종료 코드 1로 멈춘다(변화를 run_all에서 못 보고 지나치지 않게).

1. **바뀐 줄 목록을 본다** — `debug/snapshot_diff.tsv`에 전부 있다(쪽 · 사라짐/생김 · 보표 · x · y · 음이름 · 임시표 · 표기 · 확신도)
2. **줄마다 판정한다** — 육안(확대 그림), 또는 PDF 글리프 정답(`tools/classify_a17_diff.py`의 기대 표기 · 정답 머리 대응)
   - 유령이 사라짐 · 틀린 표기가 맞게 바뀜 = **고쳐짐**
   - 정답 머리의 라벨이 사라짐 = **오삭제** / 맞던 표기가 틀리게 = **새로 틀림** / 새 라벨이 정답 머리가 아님 = **새 유령**
3. 오삭제가 하나라도 있으면 그 변경은 되돌린다(CLAUDE.md 절대 조건). 새로 틀림 · 새 유령은 보고해 결정받는다
4. 판정을 WORKLOG에 적고 `python tests/test_golden_regression.py --update-snapshot`으로 갱신, 스냅샷 변경을 같은 커밋에 넣는다

## 왜 제품 명령줄로 찍나

값은 `main.py <pdf> --page N --no-debug --save-labels`를 **그대로 실행한 라벨 JSON**에서 만든다.
같은 파일의 `analyze()`(아오하루용)는 제품과 경로가 달라 — `remove_accidental_ghosts`에 `filled`를 안 넘기고 chord_rescue도 없다 —
제품에서만 도는 규칙을 한 번도 안 거친다. A-17 보정 사본이 그 경로로 「골든 통과」하고도 run_page로는 골든 C5를 지운 적이 있다
(`MEASUREMENT_PITFALLS.md` A-3b). 4개 프로세스로 나눠 17쪽이 약 1분.
