# 측정 함정 — 측정을 시작하기 전에 읽는다

같은 종류의 실수가 반복됐다. 여기 적힌 것은 **전부 실제로 겪은 것**이고, 겪은 날짜와 자리를 함께 적었다.
새 측정을 시작하기 전에 목록을 훑고 **「이번 측정이 어느 항목에 걸릴 수 있나」**를 먼저 적어 둔다.

> 판정 원칙(두 악보·쪽 단위·오삭제 0 등)은 `DECISIONS.md` §3에 있다. 여기는 **측정 방법**의 실수만 모은다.

## A. 무엇을 재는가 — 결정이 보는 값과 같은 값인가

**A-2. 기록기가 사건을 잘못 분류하면 표본이 빠진다.**

**A-2b. 사본으로 재구현할 때 목록이 중간에 다시 만들어지면 번호가 밀린다.**

**A-2c. 남의 원자료를 쓸 때 값에 무엇이 이미 들어 있는지 확인한다.**
- 2026-09-22 PR #50 ♭ 창 잘림 재현: manifest 박스에 이미 0.5sp 여백이 있는데 한 번 더 더해 43개를 58개로 셌다 (`ACCIDENTAL_GHOST_MEASURE.md` §15-2)

## B. 어떻게 재는가 — 측정 자체가 흔들리지 않는가

**B-1. 조각을 잘라내 재면 옆 글리프가 섞인다.**
- 2026-09-02 조표 ♯ 세로 위치: 글리프를 x범위로 오려 무게중심을 재니 `-0.02 / -0.06 / -2.89 step`으로 들쭉날쭉. 조표 글리프가 서로 겹쳐 옆 가로획이 섞였다 (WORKLOG 2026-09-02, `KEYSIG_REDESIGN.md`)
- 같은 날 검출 창이 G♯ 윗부분을 잘라 중심이 −0.45step 밀린 것도 같은 계열
- **징후:** 오차 방향이 제각각이면 대상이 아니라 **측정이** 틀린 것이다. **점검:** 자르지 말고 프로파일이나 이미 검출된 요소를 쓴다

**B-2. 머리 중심 추정에 의존하는 측정은 흔들린다.**
- 2026-08-28 덧줄 좌우 띠: 쇼팽 5쪽 왼쪽 0.33 / 오른쪽 0.83 — 덧줄은 멀쩡한데 탈락, 진짜 음표 11개 삭제 (`DECISIONS.md` 기각 3·4). 수평 런 길이(`verify.ledger_run_sp`)로 바꿨다
- 빈 음표는 링 안이 희어 머리 중심 x에서 덧줄이 끊긴다 (기각 2)
- **점검:** 중심이 몇 px 치우치면 값이 얼마나 변하나? 이미 있는 구조(런·성분)를 잴 수 없나?

**B-3. 결과가 화소 위상에 흔들릴 수 있다.**
- 2026-09-14: 0.5px 평행이동만으로 바흐 조표가 ♭1로 뒤집히고, 3악보에서 피해 38건 (`SUBPIXEL_SHIFT.md`)
- **점검:** 문턱 근처 결론이면 0.25·0.5·0.75px 이동에서도 같은가?


**B-4. 가로채기(spy)는 원본 모듈의 함수에만 걸린다.**
- 2026-09-27 A-8 사본 시뮬레이션: 사본 모듈의 `_analyze_one`은 **자기 사본 `_find_bars`**를 불러 원본 `_find_bars`에 건 가로채기가 비었다. 진단기는 창 정보가 없으면 「수집 창 밖 [?, ?)」로 찍어 원인을 잘못 분류할 뻔했다. 음자리표 끝을 직접 출력해 확인했다 (`KEYSIG_CLEF_GAP.md` §6)
- **점검:** 가로챈 호출 수가 0이 아닌가? 비었으면 분류하지 말고 멈춘다

**B-5. 검사가 대상을 못 재면 「통과」가 아니라 「거부」여야 한다.**
- 2026-09-28 M1 안전장치: 보표마다 잔여 기울기를 재는 방식은 **오선 검출에서 빠진 보표를 잴 수 없어** 검사를 건너뛰었고, B♭m에서 277개를 잃고도 통과였다. 「실패를 못 재서 통과」 — 조용한 부분 성공이 안전장치 안에서 재현된 것. 보표를 몰라도 되는 가로 띠 검사 + 「오선 구조가 있는데 덮은 보표가 없다」 검사로 바꿔 누수 0 (`PHOTO_PREPROCESS.md` §5-6)
- 2026-09-28 M1 구현: **잘라내기가 검사 대상을 없앴다** — 한쪽 그림자를 배경으로 보고 음자리표 쪽을 잘라낸 뒤 안전장치는 남은 영상만 보고 통과(바흐 133개 소실). 전처리가 입력을 바꾸면, 검사는 **바뀌기 전에 무엇을 버렸는지**도 봐야 한다
- **점검:** 검사가 건너뛴 대상의 수를 출력하는가? 건너뛴 것이 실패 사례면 검사가 틀렸다
- **원칙 — 「못 재면 거부」는 단계마다 따로 필요하다.** 한 단계에 넣었다고 파이프라인 전체가 안전해지지 않는다. M1에서 같은 패턴이 두 단계에서 따로 나왔다: ① 안전장치가 **오선을 못 찾은 보표**를 건너뜀(→ 못 찾은 보표 검사) ② 잘라내기가 **검사 전에 내용을 버림**(→ 오선 같은 내용이 잘리면 안 자름). 입력을 줄이거나 버리는 단계(잘라내기 · 필터 · 후보 제외)를 새로 넣을 때마다 「이 단계가 버린 것을 뒤 검사가 볼 수 있나」를 묻는다

**B-6. 합성 영상의 여백 경계는 가짜 입력이 된다.**
- 2026-09-28 M1 합성: 흰 여백을 붙이고 되돌린 영상을 그대로 쓰자 원본-여백 경계가 가로 전체 폭의 가짜 선이 되어 오선 문턱을 올렸고(A-12), 순수 회전인데 23개가 사라졌다. 앞선 측정(`recover`)은 원래 크기로 잘라내 이 문제가 없었다 — 두 합성 경로의 차이를 먼저 의심해 확인했다
- **점검:** 합성 결과가 앞선 측정과 안 맞으면 **합성 경로**(여백·잘라내기·보간 횟수)부터 대조한다
