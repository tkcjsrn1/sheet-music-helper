## 정정 — 01번 문서의 "♯은 무사, ♭5·♭6만 틀린다"는 낙관적이었다

최종 조표 개수가 아니라 **내부 막대 수**를 직접 세면 그림이 다르다.

| 조표 | dx0 막대 | 실패 위상 막대 | 최종 결과 | 살아남은 이유 |
|---|---:|---:|---|---|
| ♭1 | 2 | 2 (불변) | ♭1 ✓ | 증가 자체가 없음 |
| ♭2 | 3 | **4** | ♭2 ✓ | `n_holes`가 잘라줌 |
| ♭3 | 4 | **5** | ♭3 ✓ | `n_holes` |
| ♭4 | 5 | **6** | ♭4 ✓ | `n_holes` |
| **♭5** | 6 | **7** | **♭6 ✗** | — |
| **♭6** | 7 | **8** | **♭7 ✗** | — |
| ♭7 | 8 | **9** | ♭7 ✓ | `min(n_flat, 7)` 상한 |
| ♯1 | 2 | **3** | ♯1 ✓ | ♯ 분기가 `singles`를 안 봄 |
| ♯2 | 5 | 5 (불변) | ♯2 ✓ | |
| ♯3 | 7 | 7 (불변) | ♯3 ✓ | |

(위상은 dx −0.25 / +0.75, 300dpi)

**막대 증가는 ♭2~♭7 전부에서 일어난다.** 결함은 보편적이고, 서로 다른 두 안전장치가
우연히 5종을 가려주고 있을 뿐이다.

- `n_flat = min(len(singles), n_holes)` 의 **`n_holes`가 ♭1~♭4를 구한다**
- **`min(n_flat, 7)` 상한이 ♭7을 구한다**
- **♭5·♭6은 그 틈에 떨어진다** — 이 둘은 `n_holes`도 함께 늘어 `min()`이 막지 못한다
  (Codex가 이미 관측한 "원본 holes 중앙값 5→6, 6→7"이 이것이다)

**♯의 면역은 구조적이고 확인됐다.** ♯1도 막대가 2→3으로 늘지만, 짝을 못 지은 막대가
`singles`로 빠지고 **♯ 분기는 `pairs`만 쓰고 `singles`를 보지 않는다.**

## 코드상의 원인 — 가드가 한쪽에만 있다

`modules/clef_keysig.py` `_vote_key_signature`:

```python
# ♯ 경로 — 보호됨
if (sp*0.3 <= consensus[i+1] - consensus[i] <= sp*0.55
        and _same_glyph(found, consensus[i], consensus[i+1])):
    pairs.append(...)          # 쌍으로만 인정
else:
    singles.append(...)
if pairs:
    return min(len(best), 7), "♯", ...     # singles를 보지 않는다

# ♭ 경로 — 무방비
if singles:
    n_holes = int(np.median([c.holes for c in found]))
    n_flat = min(len(singles), n_holes)    # 글리프 귀속 검사도 간격 조건도 없다
```

보간으로 한 ♭의 기둥과 배가 두 열로 갈리면 **두 개의 single**이 되고, 그대로 ♭ 2개다.
`_same_glyph`에 해당하는 검사가 ♭ 쪽에는 없다.

## 수정 방향

**♭ 분기에도 글리프 귀속 검사를 붙여 같은 ♭에서 나온 `singles`를 합친 뒤 센다.**
새 개념이 아니라 ♯ 쪽에 이미 있는 장치를 ♭ 쪽에도 거는 것이다.
리샘플링이 늘지 않고 새 문턱을 발명하지도 않는다.

**단 `_same_glyph`를 그대로 쓰면 안 된다.** `KEYSIG_PAIR_Y_STEP = 1.75`는 **♯의 두
세로획** 기준이고, ♭은 기둥과 배의 y 범위가 다르다. **♭용 문턱은 실측 분포에서
유도해야 한다** — 정상 ♭1~♭7의 (기둥, 배) y 간격 분포와, 보간으로 갈린 가짜 쌍의
분포가 겹치지 않는 지점을 찾는다. COLLAB §3-2 절차 그대로다.

**하지 말 것**
- 클러스터 폭 `3.0`px·높이 상한·투표선을 숫자로 조정 — DECISIONS 기각 이력과 같은 길이다
- 전체를 sp 단위로 정규화하는 리팩터링 — 3.5px/20.75=0.169 vs 문턱 3.0px=0.145로
  **대소 관계가 그대로여서 버그가 안 풀리고**, 정규화에 필요한 리샘플링이 이 버그의
  방아쇠다(아래 dpi 표)
- **`n_holes`에 기대는 것** — 그건 설계된 판정이 아니라 우연히 맞아주는 안전망이다.
  ♭1~♭4가 지금 맞는 이유가 그것뿐이라는 사실이 오히려 위험 신호다

## dpi 분포 — "300dpi는 운이 좋다"도 정확하지 않았다

바흐 x 0.0~1.0 step 0.05 (21조건).

| dpi | 처리 폭 | 불일치 | 비고 |
|---|---:|---:|---|
| 150 | 1241px | 8/21 (38%) | |
| 200 | 1654px | 11/21 (52%) | |
| 250 | 2067px | 11/21 (52%) | |
| **299** | 2473px | **17/21 (81%)** | 01번 문서 측정 |
| 300 | 2481px | 5/21 (23%) | |
| 400 | 3308px | 5/21 (23%) | |
| 600 | 4961px | 3/21 (14%) | **21조건 중 14개가 예외** (기존 600dpi 실패) |

정확한 서술: **바흐는 어느 dpi에서든 23~52% 틀리고, 이웃한 dpi 사이에서 예측 불가능하게
튄다**(299=81% vs 300=23%). 300이 유일하게 좋은 게 아니라 300·400이 좋은 편이고
200·250이 나쁜 편이다. 600dpi는 대부분 예외이며 실행된 7개 중 3개가 틀렸다.

## 채택 조건 — 01번의 5~10에 더한다

11. **검증은 최종 조표 개수가 아니라 막대/클러스터 수로 한다.** 최종 개수로만 보면
    ♭1~♭4·♭7이 "원래 맞았다"로 보여 회귀를 통째로 놓친다. 이번 표가 그 증거다.
12. **`n_holes`와 `min(…,7)`을 끈 상태에서도 정답이 나오는지 확인한다.** 두 안전망이
    가리고 있어서, 그것들을 켠 채로는 수정이 실제로 됐는지 알 수 없다.
13. ♭1~♭7 **일곱 종 전부**를 검증 대상에 넣는다. ♭5·♭6만 보면 안 된다.
