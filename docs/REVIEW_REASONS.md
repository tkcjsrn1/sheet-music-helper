# 라벨 확인 이유 안내 — 2026-10-16 경량 준비

현재 main의 `modules/labels_io.py` 신호 목록(`_HIGH_PRECISION`, `_LOW_PRECISION`, `_REVIEW_REQUIRED`, `_RECORDED_ONLY` 및 `flags_of`)을 읽어 대응했다. 이 문서는 판정 조건의 채택 기록이 아니며 `labels_io.py`는 수정하지 않는다.

기존 GUI는 신호 이름을 나누지 않고 `confidence`에 따라 주황 점선(check), 연한 글씨(caution), 쪽별 개수·순회만 제공한다. `double_acc`, `flat_propagated`, `beam_gap`, `narrow_hole`, `text_row` 모두 이 공통 경로로 표시된다. §1-42 채워진 머리도 새 이름이 아니라 기존 `beam_sloped`를 쓴다.

이번 후보는 `user_messages.label_review_reason()`에서 설명만 만들고 라벨 수정/삭제 창에 선택 사유를 보여 준다. 선택·N/P 순회·되돌리기 후 새 선택으로 바뀌고, 선택이 없으면 이전 사유를 지운다. 여러 사유는 중복 없이 한 설명으로 이어 쓰고 창 너비에 맞춰 줄바꿈한다. 예외를 지원한다고 확신하거나 유령이라고 단정하지 않는다. `bb/##`는 글꼴에 없는 기호가 네모로 나오는 문제를 피한 화면 표기다.

check/caution인데 신호가 없거나 모르는 신호만 있으면 원본과 대조하라는 일반 안내를 쓴다. flags 형식이 목록이 아니어도 창을 깨뜨리거나 문자열 일부를 신호로 읽지 않는다. certain은 추가 확인 사유가 기록되지 않았다고만 쓰며 정답 보장으로 해석하지 않는다. 사용자 수정 라벨은 「사용자 수정 / 원래 판정」으로 구분하고 원래 flags·confidence는 보존한다. 사용자가 새로 추가한 라벨은 원래 인식 판정이 없으므로 「사용자가 추가한 라벨」로 표시한다.

범위: `gui.py`의 수정 창·선택 정보, 기존 `user_messages.py`, `tests/test_review_reasons.py`. 파이프라인·음표·신호·등급·렌더러·저장 JSON·설정·의존성 변경 없음. 추가 테스트는 run_all의 기존 자동 탐색 대상이다.

검증: 사유 안내가 없던 상태의 실패 → 구현 후 경량 단위 통과, 잘못된 flags 형식의 실패 → 형식 확인 후 통과. GUI 선택 콜백의 사유 갱신·해제, 최근 신호와 전체 등급 신호 대응, 복수 사유·중복·원본 라벨 무변경을 확인했다. 실제 창/전체 검사/기본 PNG·JSON 6파일 바이트 대조/골든711/PDF17은 **미실행**. 사용자 지시대로 CLI 조바꿈 측정 뒤 별도 지시를 받아 진행한다. 이 후보는 아직 4fc3343 exe에 들어 있지 않다.
