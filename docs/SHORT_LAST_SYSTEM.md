# 짧은 마지막 시스템 누락 — 오선 문턱 측정 (TASKS [2](b) · 2026-10-02 · 측정만, 제품 코드 무변경)

> **결론 먼저**: 제품 보표는 그대로 두고 **보표가 없는 y 구간에서만** 낮은 문턱으로 5줄 묶음을 더 찾는 사본이
> Verovio 18 → **20/20**, 기울였다 되돌리기 251 → **254/255**(Aoharu 0.5px 이동에서 놓친 보표 3개를 되찾음).
> 다른 세트는 모두 그대로 맞고, **오검출(보표가 아닌 것을 보표로) 0** — 462 입력 중 더한 7개 전부 눈 판정 진짜.
> 거르는 규칙은 「보표 5줄은 같은 x 범위를 덮는다」(x 겹침 ≥ 0.53). **약점**: 휜 오래된 스캔(Satie)의 진짜 보표 2개가 0.47 · 0.52로 걸러진다 — 지금 제품도 놓치는 것.

도구 `tools/measure_short_system.py`(collect · eval), 원자료 `debug/short_system/`(커밋 안 함), 그림 `docs/review/short_system/`.

## 0. 원인 (Verovio 측정 §2-3 확인)

`preprocess.detect_staff_lines` 문턱 = `max(0.6 × ref, 0.25 × 폭)`, ref = 가장 긴 가로선 행.
Verovio는 마지막 줄을 양끝 맞춤하지 않는다 — Mozart L 마지막 시스템 오선 행합 1,046(문턱 1,201) · Schumann L 243(**폭 항 525에도 걸림**).
그래서 0.6만 낮춰서는 Schumann L이 안 고쳐진다 — 두 항 모두의 문제다.

## 2. 후보(사본)

1. 제품 보표 위아래 1sp 띠 **밖**에서, `staff_line_profile` 봉우리를 높이 ≥ 열림 커널 길이(`폭 // 30` — 제품의 「가로선」 정의 그대로)로 다시 찾는다
2. 연속 5개가 제품 `group_into_staves` 검증 조건(간격 표준편차 ≤ 0.25 × 평균 · 쪽 간격의 0.6~1.6배)을 넘으면 후보
3. **x 겹침**(5줄 공통 x 구간 / 전체 x 구간) ≥ 0.53이면 보표로 더한다

**기존 보표 · 그 라벨은 바뀔 수 없다**(1의 띠 밖만 본다).

### x 겹침 문턱 — 기보 규칙 + 두 분포

| | 값 |
|---|---|
| 진짜: 제품이 이미 찾은 보표 3,662(사진 · 압박 입력 포함) | 1백분위 **0.84** · 짧은 시스템 4개 **1.00** |
| 가짜: D♭ 6쪽 페달 괄호선 · 보정 없는 회전 0.5° 오선 조각 | **−0.72** · 최대 **0.33** |
| √(0.84 × 0.33) | **0.53** |

**길이비(최소 행합 / 최대 행합)는 쓰지 않는다** — 회전 조각 묶음이 0.99까지 나와 못 가른다.

## 4. 약점 · 안 한 것

- **진짜 쪽 여유**: 깨끗한 입력은 1.00, 제품 보표 1백분위 0.84지만 휜 스캔은 0.47~0.52 — 0.53 아래. 문턱을 0.40(0.33과 0.47 사이)으로 내리면 Satie 2개를 더 잡지만 근거가 한 스캔뿐이라 제안하지 않는다
- **음악적 오검출 경로**: 표 · 괄호선처럼 **같은 길이 · 등간격 5줄**인 것은 이 규칙으로 못 거른다(462 입력에서 0건)
- 라벨 영향(더한 보표의 음표 · 음자리표 · 조표 투표 참여)은 구현 승인 뒤 — 조표 투표에 보표가 늘면 문턱(과반)이 바뀐다
- M1 안전장치(`check_photo`)와의 관계: 사진 세트에서 더한 보표 0이라 거부 수 그대로(18). 구현 때 순서를 확인
