## 1. 보정 후 조표 뒤집힘

**튀는 이유 — 틈의 잔여 잉크.** 음자리표 클러스터는 「열 잉크 ≥ 0.5sp」 열이 이어지는 동안 커지고, 그 아래로 떨어지는 열이 `max_g`개를 넘어야 끝난다(`clef_keysig._analyze_one` 1단계). 헤더 띠(보표 ±1.5sp)의 열 잉크를 보면:

**둘째 원인(Aoharu 한정)** — ♯ 두 세로획 간격이 0.52sp라 closing 뒤 붙는다. 폭이 `max_w` 0.45sp를 오가며 `_split_merged_bars`의 성공·실패와 분할 위치(±5px)가 갈린다. `DECISIONS.md` §1-5에서 관측한 그대로다. 0.5px 평행이동으로 뒤집히는 Aoharu는 이쪽이다(보표 6·7·9·11 막대가 286 → 281). **(2026-09-28) A-8 뒤에는 이 뒤집힘이 CUBIC · LANCZOS4 · 2배에서 0이 됐다** — 획 붙음 자체는 그대로라 잠재 위험(TASKS A-9)으로만 남긴다.

**집계가 약한 곳** — 규칙은 멀쩡하지만 **여유가 얇다**(원본 여유: Aoharu +3, B♭m +1, 바흐 −1). 흔든 뒤에는 Aoharu 여유가 +0~+2로 떨어진다. 위 두 원인이 보표 두세 개만 빼도 판정이 넘어간다.

### 1-2. 보간 방식 비교 (`measure_keysig_resample.py sweep`)

기울이기는 INTER_LINEAR로 고정하고 **되돌리기만** 바꿨다. 되돌리기는 정확히 −θ다(추정 오차 제외). 각도는 기존 8각에 8각을 더한 16각(0.15~8°, −1°, −3° 포함)이다.

| 되돌리기 방식 | 기존 8각 (24회) | 16각 (48회) | 악보별 (16각) | 0.5px 평행이동에서 뒤집힘 |
|---|---:|---:|---|---|
| INTER_LINEAR (지금 도구 기본) | 5 | 8 | Aoharu 4 · B♭m 4 | 바흐 ♭1 |
| INTER_NEAREST | 9 | **19** | Aoharu 13 · 바흐 5 · B♭m 1 | Aoharu **조표 없음** |
| INTER_CUBIC | 2 | 6 | Aoharu 5 · B♭m 1 | Aoharu ♯1 · 바흐 ♭1 |
| INTER_LANCZOS4 | **1** | **2** | Aoharu 2 | Aoharu ♯1 · 바흐 ♭1 |
| 2배(CUBIC) → 되돌림(LINEAR) → 축소(AREA) | 3 | 5 | Aoharu 5 | Aoharu ♯1 · 바흐 ♭1 |

- **NEAREST가 가장 나쁘다.** 보간을 안 하는 것이 답이 아니다 — 계단이 막대 폭과 run을 더 크게 흔든다
- **LANCZOS4가 가장 적지만 0이 아니다.** Aoharu 0.7° 뒤집힘의 원인도 똑같이 `clef_end` 튐(보표 4·6 창 밖)과 분할 실패였다
- **2배 확대는 이득이 없다**(LINEAR 8 → 5지만 CUBIC 6과 같은 수준)
- 0.5px 평행이동(기울기 0)에서도 LANCZOS4·CUBIC·2배 모두 뒤집힌다. 바흐 ♭1은 `SUBPIXEL_SHIFT.md` §4의 기둥 가장자리 경로다

**판정: 보간 하나로는 해결 안 된다.** 조표 판정을 손봐야 하며, 이는 별도 작업이다(`clef_keysig.py`, Claude 담당). 고칠 곳은 교차 투표보다 앞이다. 하나는 **음자리표 끝 판정이 오선 잔여 잉크에 휩쓸리지 않게** 하는 것이고, 다른 하나는 **♯ 붙은 획의 분할**이다. 이 조사에서는 고치지 않았다(`DECISIONS.md` 절차 1~8을 밟아야 한다).

## 2. 각도 추정기 — 원근·곡면 (`measure_skew_local.py`)

합성은 추정기 검증용 **최소한**이다. 변형이 해석적으로 알려져 있어서, 보표마다 가운데 줄을 사진 좌표로 옮겨 **참 기울기**를 계산했다. 잔여는 「|tan(참−추정)| × 오선 길이」를 sp로 나눈 값이고, 기준은 보표 소실 없음 0.21sp(`PORTABILITY.md`)다.

| 변형 (+2° 회전) | 보표 참 기울기 범위 (B♭m) | **전역 추정 1개** — 기준 넘는 보표 (B♭m · Aoharu · 바흐) | **보표별 추정** — 기준 넘는 보표 |
|---|---|---|---|
| 회전만 (대조) | −2.00° | 0/8 · 0/12 · 0/8 | 0 · 0 · 0 |
| 위아래 원근 k=0.20 | −2.00° | 0 · 0 · 0 | 0 · 0 · 0 |
| **좌우 원근 ks=0.05** | −3.61 ~ −0.86° | **7/8 · 11/12 · 7/8** (잔여 최대 3.1 · 3.4 · 2.2sp) | 0 · 0 · 0 (≤0.06sp) |
| 좌우 원근 ks=0.10 | −5.22 ~ 0.27° | 7/8 · 11/12 · 7/8 | 0 · 0 · 0 (≤0.07sp) |
| 좌우 원근 ks=0.20 | −8.42 ~ 2.54° | 7/8 · 11/12 · 7/8 (최대 15.4sp) | 1/8 · 1/12 · 0/8 |

- **위아래 원근(윗변이 좁은 사다리꼴)은 가로선을 가로로 둔다** — 보표 기울기가 안 바뀐다. 대신 위아래로 **가로 배율**이 달라진다(§3 해상도)
- **좌우 원근이 보표마다 기울기를 벌린다.** 전역 추정은 그 사이 어딘가를 골라 **한 보표(가운데 근처)만** 맞춘다

| 곡면 (오른쪽 끝으로 A·t² 처짐) | 곡률 잔차 (직선 하나로 폈을 때) | 전역 1개 | 보표별 1개 | 보표를 반으로 나눴을 때 곡률 |
|---|---|---|---|---|
| 1sp | 0.12~0.14sp | 0 · 0 · 0 | 0 · 0 · 0 | 0.03sp |
| **3sp** | **0.37~0.41sp** | 0 · 0 · 0 | **5/8 · 0/12 · 3/8** | 0.09~0.10sp |
| 8sp | 0.98~1.10sp | 2/8 · 12/12 · 2/8 | 8/8 · 12/12 · 3/8 | 0.23~0.26sp |
| 좌우 원근 0.10 + 휨 3sp | 0.35~0.40sp | 8/8 · 11/12 · 7/8 | 4/8 · 0/12 · 4/8 | 0.09~0.10sp |

- **곡면에서는 보표 하나에 각도 하나가 정의되지 않는다.** 휨 3sp에서 곡률만 0.4sp로 이미 기준의 두 배다. 보표별 추정이 전역 추정보다 오히려 나쁜 경우도 있다. 휜 선에서 투영이 가장 뾰족해지는 각은 현(弦)의 기울기가 아니라 **더 가파른 쪽 구간**을 따르기 때문으로 보인다(확인 안 함)
- **보표를 가로로 나눠 조각마다 맞추면 곡면도 따라간다**(반으로 나누면 3sp 휨이 0.10sp). 8sp 휨은 반으로도 부족하다 → 조각을 더 잘게 나누거나 오선 추적이 필요하다
- 바흐의 「좌우 원근 + 휨」에서 전역 추정기가 **+0.19°**를 냈다(참값 −1.56 ~ 2.41°). 거친 탐색(1/4 축소)이 다른 봉우리를 잡은 것으로 보인다 — 전역 추정기도 단조롭게 믿을 수 없다

**보표별 추정의 전제** — 이 측정은 보표 위치를 **참값으로 알고** 띠를 잘랐다(상한). 실제로는 보표를 먼저 찾아야 하는데, 기울어진 채로는 오선 검출이 0.20°(0.4sp 밀림)에서 무너진다(`PORTABILITY.md`). 그래서 아래 설계는 **귀퉁이로 크게 편 다음 보표 단위로 다듬는** 두 단계로 짠다.

## 3. 전처리 설계안 (구현 안 함)

### 3-0. 원칙 — 측정에서 나온 것

1. **재표본화는 한 번만 한다.** 한 번 할 때마다 라벨 1~4%가 흔들리고(`PORTABILITY.md` 회복 상한) 조표도 뒤집힌다(§1). 원근 · 회전 · 배율을 **변환 행렬 하나로 합쳐** `warpPerspective` 한 번으로 끝낸다. 곡면 보정이 따로 필요하면 그것까지 합친 `remap` 한 번으로 한다
2. **조표·음자리표가 원본과 같은가를 반드시 검증한다.** A-8로 뒤집힘이 거의 없어졌지만(§1-3) 3악보 1쪽 합성 측정이고, 바흐 ♭1 경로(A-10)는 남았다. 잔여 밀림만 보면 안 된다(Aoharu는 0.05°에서 뒤집혔었다)
3. 성공 판정을 예외 유무나 보표 수로 하지 않는다(`PORTABILITY.md` 조용한 부분 성공)
4. **보간은 NEAREST만 피한다.** A-8 뒤 LINEAR · CUBIC · LANCZOS4 · 2배는 조표 뒤집힘이 모두 0이라 조표로는 고를 근거가 없다 — **라벨 기준으로 고른다**(미측정). 2배 확대는 이득이 없으니 안 한다

### 3-1. 단계

| 단계 | 방법 | 이 단계에서 검증할 것 |
|---|---|---|
| **0. 방향** | EXIF 회전을 적용한다. 90° 단위 회전은 보간 없는 transpose로 | 가로·세로 뒤바뀜 없음 |
| **1. 조명 보정** | 그레이스케일에서 **배경 추정 후 나누기**(flat-field). 배경 = 축소 영상에 글리프보다 큰 커널로 closing(또는 median) 후 확대. 커널은 sp를 모르므로 짧은 변의 비율로 잡고, **3단계 뒤 sp로 재검증**한다. 그림자 경계가 날카로우면 커널이 못 따라가므로 그 경우를 따로 센다 | 종이 영역 밝기 분산이 줄었는가, 오선 대비(선/배경)가 원본 PDF 렌더와 비슷한가. 지금 `binarize`는 **blockSize 25px 고정 적응형 이진화**라 해상도에 묶여 있다 — 조명 보정은 이진화를 바꾸지 않고 앞에서 입력을 고르게 만드는 쪽으로 한다 |
| **2. 네 귀퉁이 (거친 원근)** | 흰 종이·어두운 배경은 유리하다. 축소 영상(긴 변 ~1000px)을 Otsu로 나눠 가장 큰 밝은 윤곽을 찾고, `approxPolyDP`로 사각형 후보를 얻는다. 그다음 **변마다 윤곽점에 직선을 맞춰(`fitLine`) 교점으로 귀퉁이를 원해상도 서브픽셀로 다시 구한다**. 종이가 화면을 꽉 채워 변이 안 보이면 이 단계를 건너뛰고 4단계로 간다 | 귀퉁이 재투영 오차. **2px(300dpi 환산) 안이어야 이 단계만으로 기울기 기준을 넘지 않는다**(아래 표) — 현실적으로 어려우므로 이 단계는 **거친 보정**으로만 쓴다 |
| **3. 목표 해상도** | dpi가 아니라 **sp로 맞춘다.** 사진은 종이 크기·거리를 몰라 dpi가 정의되지 않는다. 원근을 편 뒤 오선 간격을 추정하고(행 투영 자기상관; PR #45의 고해상도 간격 추정과 같은 문제), 배율을 원근 행렬에 곱해 **한 번에** 변환한다. 목표는 **검증된 범위 sp 11.6~20.8px 안**(Aoharu 11.6 · PDF 300dpi 19.7~20.8)이다. 지금 쓰는 blockSize 25·커널들이 이 범위에서만 확인됐다. 이보다 크면 줄이고, 작으면 키우지 말고 **경고**한다(확대는 없는 정보를 만들지 않는다 — A-8 뒤 2배 확대는 조표 뒤집힘에서 이득 0) | 보표마다 sp가 목표 범위 안인가, 보표 사이 sp 차이(위아래 원근 잔여) |
| **4. 보표 단위 다듬기 (고운 원근·곡면)** | 3단계 영상에서 오선을 찾고, **보표를 가로로 조각내**(측정: 반으로 나누면 3sp 휨 → 0.10sp. 조각 폭은 실제 사진에서 정한다) 조각마다 행 투영으로 y 어긋남을 잰다. 그 값으로 열마다 세로 이동량 지도를 만들어 **2~3단계 행렬과 합친 `remap` 한 번**으로 다시 만든다(원본에서 한 번에) | 보표마다 **좌우 끝 y 차이 ≤ 0.21sp**(`PORTABILITY.md`의 기준), 곡률 잔차 |
| **5. 최종 확인** | 기존 파이프라인 그대로 | 조표·음자리표가 **같은 원본의 정답**과 같은가(§3-0 원칙 2), 「악보 줄 N개」가 실제 줄 수와 같은가, 소스 정답이 있는 합성본에서 음표 → 라벨 방향 오삭제 |

**귀퉁이 오차가 남기는 것** (`measure_skew_local.corner_error`, A4 300dpi, 좌우·위아래 원근 0.10 + 2°, 귀퉁이마다 ±ε px 균등 잡음, 300회):

| ε | 기울기 잔여 p95 | 0.21sp 넘는 비율 | 페이지 안 세로 배율 차 p95 | **한 보표 폭 안** 배율 차 p95 |
|---:|---:|---:|---:|---:|
| 2px | 0.16sp | 0% | 0.43% | 0.12% |
| 5px | 0.39sp | 46% | 1.08% | 0.30% |
| 10px | 0.81sp | 83% | 2.11% | 0.56% |
| 20px | 1.51sp | 95% | 4.27% | 1.28% |

### 3-2. A-6(게이트 정수 경계)이 필수가 되나 — **된다고 본다**

`SUBPIXEL_SHIFT.md`의 「A-6과 겹침 0」은 **평행이동 0.5px**에서 잰 것이다. 그때는 덩어리 모양이 보간으로 끊기거나 붙는 쪽이 원인이었고, 문턱의 정수 경계와는 같은 덩어리가 아니었다. **그 결론은 평행이동·회전에만 해당한다.**

원근 보정은 다른 것을 남긴다. 파이프라인은 보표마다 **sp 하나**를 쓰는데, 원근이 덜 펴지면 같은 보표 안에서 **실제 배율이 위치마다 달라진다**. 위 표에서 귀퉁이 오차 5~10px이면 한 보표 폭 안에서 0.30~0.56%, 20px이면 1.28%다. 곡면은 여기에 더해진다(합성하지 않음).

이 불일치를 흉내 내려고 보표 sp를 ±p% 어긋나게 줬다(`measure_subpixel_shift.run` + `moved_staves(dsp)`, 영상은 그대로):

| sp 어긋남 | 바흐 (라벨 185) | B♭m (270) | Aoharu (226) |
|---|---|---|---|
| −0.5% | 0 | 표기 1 | 0 |
| +0.5% | 음고 3 · 소실 1 | 0 | 0 |
| −1% | 0 | 음고 2 · 소실 1 · 표기 1 | 음고 1 |
| +1% | 소실 2 · 음고 3 · 신규 2 | 0 | 음고 3 |
| −2% | 0 | 음고 2 · 소실 1 · 표기 3 | 소실 1 · 음고 6 · 신규 1 |
| +2% | 소실 3 · 음고 4 · 신규 5 | **소실 17** · 음고 4 · 표기 6 · 신규 16 | 음고 4 · 신규 1 |
| ±3% | 3 ~ 13 | 12 ~ 62 | 19 ~ 23 |

- 기존 A-6 측정(δsp=−0.10px ≈ −0.5%, 라벨 변화 0)은 바흐·Aoharu에서 재현되고, B♭m은 표기 1개가 다르다(원인 확인 안 함). **반대 방향(+0.5%)은 예전에 안 쟀다** — 바흐에서 +0.5%에 4개가 바뀐다
- 1%에서 세 악보 모두 바뀌고, 2%부터 B♭m에서 소실이 17개로 뛴다

**판정** — 사진 입력에서는 보표 안 배율이 0.5~1% 흔들리는 것을 피하기 어렵다(귀퉁이 5~10px). 그 범위에서 라벨이 바뀌므로 A-6(부분 픽셀 게이트)이나 **보표 구간별 sp**가 필요해진다. 3-1의 4단계가 보표를 조각내 펴는 것도 이 불일치를 줄이는 쪽이다. **단서** — 이 흔들기는 sp를 쓰는 곳 전부(크기 게이트 **와 음고 계산의 반칸 환산**)에 들어간다. 「음고」 변화 중 얼마가 A-6 게이트 탓인지는 **분해하지 않았다.** A-6 착수 전에 게이트별 분해(`measure_subpixel_shift.gate_flips`)를 먼저 해야 한다.

### 5-3. 그러나 실제 사진에는 좌우 원근이 섞인다 — 「기울기만」의 경계 (`measure_skew_local.py --fine · --bands`)

좌우 원근 ks(오른변이 ks만큼 짧아짐) + 회전 2°. 보표별 잔여 = |tan(참 − 추정)| × 오선 길이 / sp, 기준 0.21sp.

| ks | **전역 각 하나** 잔여 최대 (넘는 보표) — B♭m / Aoharu / 바흐 | **가로 띠 10개 + θ(y) 직선** — 보표 위치 모름 | 보표별 (위치 앎, 상한) |
|---:|---|---|---|
| 0 | 0.00 / 0.00 / 0.00 | 0.01 / 0.00 / 0.00 | ≤ 0.02 |
| 0.0025 | 0.14 (0) / 0.15 (0) / 0.10 (0) | — | ≤ 0.03 |
| 0.005 | **0.27 (3/8) / 0.27 (3/12)** / 0.19 (0) | 0.04 / 0.02 / 0.02 | ≤ 0.02 |
| 0.01 | 0.67 (6/8) / 0.57 (8/12) / 0.37 (4/8) | 0.07 / 0.04 / 0.05 | ≤ 0.03 |
| 0.02 | 1.43 (6/8) / 1.03 (10/12) / 0.89 (6/8) | **0.14 / 0.09 / 0.11 — 전부 통과** | ≤ 0.03 |
| 0.05 | (§2) 3.1 / 3.4 / 2.2 | **1.03 (6/8) / 0.13 (0) / 0.35 (3/8)** | ≤ 0.06 |
| 0.10 | (§2) 6.6 / 6.5 / 4.4 | 2.36 / 0.65 / 1.41 — 실패 | ≤ 0.07 |

- **전역 각 하나는 ks ≈ 0.0025까지.** 핀홀 근사로 ks ≈ (종이 폭/거리)·sin(좌우 기울기)이고 A4를 30cm에서 찍으면 폭/거리 ≈ 0.7이므로 **좌우로 약 0.2°** — 손으로는 못 맞춘다(근사 환산, 실측 아님)
- **가로 띠별 추정(보표 위치 몰라도 됨)은 ks ≈ 0.02(약 1.6°)까지** 각도를 맞춘다. 좌우 원근은 기울기를 y에 따라 거의 선형으로 바꾸기 때문이다. 흰 여백 띠는 중앙값에서 1° 넘게 벗어나면 뺐다
- **각도만 맞춰서는 부족하다.** 좌우 원근은 보표 안에서 **좌우로 세로 배율**도 바꾼다(ks=0.02면 오른쪽 끝 sp가 2% 작다). 회전·전단은 이것을 못 편다. sp 1% 불일치에서 세 악보 모두 라벨이 바뀌고 2%에서 B♭m 음표 17개가 사라졌다(§3-2) → **실제로 버티는 한계는 ks 0.005~0.01(좌우 약 0.4~0.8°)로 추정**한다. 라벨로 재지 않았다
- 위아래 원근(k)은 보표 기울기를 안 바꾸고 보표마다 sp만 다르게 한다 — 파이프라인이 보표마다 sp를 따로 재므로 **기울기 보정의 벽은 아니다**

### 5-5. 최소 구현 범위 제안 — 「기울기만 보정」은 어디에 쓸 수 있나

**M1. 전역 회전 보정** — 행 투영 각도 추정 → `warpAffine` 한 번(LINEAR 이상, NEAREST 금지)

- 되는 입력: 스캐너·복합기(평판이라 원근 없음), 거치대로 **정면에서** 찍은 사진. 화면 캡처는 원래 안 기울어 필요 없다
- 안 되는 입력: 손으로 든 사진 대부분 — 좌우 0.2°를 넘는 원근
- **반드시 같이 넣을 것 — 안전장치**: 보정 뒤 **보표마다 좌우 끝 y 차이를 재서 0.21sp를 넘는 보표가 있으면** 「사진이 비스듬합니다. 정면에서 다시 찍어 주세요」로 멈춘다. 예외 유무로 성공을 판정하지 않는다(조용한 부분 성공)

**M2. 가로 띠별 각도 + θ(y) 전단** — 귀퉁이 없이 원근 일부를 흡수 (M1이 되면 다음)

- 같은 안전장치

**M3. 귀퉁이 원근 변환 + 띠별 다듬기** — 손 촬영 본격 지원. 귀퉁이 2px 정밀도가 관건(§3-1)
