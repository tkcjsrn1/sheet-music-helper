# [B-1] 붙은 화음 머리는 어느 단계에서 사라지나 (2026-09-29)

**측정만 했다. 제품 코드 무변경.** 도구 `tools/measure_chord_fragment.py`, 원자료 `debug/chord_fragment.log` · `debug/chord_binarize.log`,
그림 `docs/review/chord_split/fragment_stages_1.png` · `_2.png`. 앞 단계: `docs/CHORD_SPLIT_MEASURE.md`.

대상: [B] 1단계에서 분할 앞에서 사라진 붙은 화음 머리 **254개**(게이트 탈락 185 + 성분 없음 69). PDF 17쪽.
대조군: 같은 오선 위치(선 위 / 칸 사이 × 오선 안 / 덧줄 구역)의 **검출된 단일 머리 4108개** · 검출된 화음 머리 253개.

## 결론 먼저

**원인은 이진화다.** `preprocess.binarize`의 적응형 이진화 창 `blockSize=25`가 **절대 px**다.
300dpi(sp ≈ 19.5px)에서 3도로 쌓인 꽉 찬 머리 두 개는 세로 약 36px(≈1.9sp)짜리 검은 덩어리가 되는데, 창(25px)이 그보다 작아
덩어리 안쪽 화소가 「주변 평균보다 어둡지 않다」로 판정되어 **흰색으로 뚫린다**. 원본에서는 꽉 찬 머리가 이진화 뒤 속 빈 「8」자 모양이 되고,
타원 opening(0.65 × 0.5sp)이 얇아진 테두리를 깎아 머리가 0.3~0.4E 조각으로 남는다 → 면적 · 높이 게이트에서 탈락.

단일 머리(≈1sp)는 창 안에 들어가 거의 안 뚫리고(가운데 작은 점 정도), 오선 · 덧줄 제거는 누락과 **무관**하다(아래 3번).

## 1. 소실 단계 (머리 영역 R = 정답 중심 0.6 × 0.45sp 타원 안 가장 큰 조각, 「살아 있음」 = 면적 ≥0.5E · 높이 ≥0.68sp)

| 소실 단계 | 화음 · 누락 (254) | 화음 · 검출 (253) | 단일 · 검출 (4108) |
|---|---:|---:|---:|
| S0 이진화 | 4 | 45 | 102 |
| S1 오선 제거 | 13 | 28 | 82 |
| S2 덧줄 제거 | 0 | 0 | 0 |
| S3 세로 메움 | 0 | 0 | 0 |
| **S4 opening** | **237** | 91 | 0 |
| S5 성분 | 0 | 0 | 1 |
| 끝까지 살아 있음 | — | 89 | 3923 |

- S0 · S1에서 「죽는」 것은 **빈 음표(s1 · s0)로 보인다**(그림의 사례 · 4번 표의 R 안 비율과 맞음, 행별 글리프는 안 셈) — 링이라 R 안 면적이 원래 작다. 빈 음표는 opening이 아니라 구멍 검출 경로로 잡으므로 이 표의 대상이 아니다
  (단일 머리 184개가 S0 · S1에서 「죽고도」 검출된 이유)
- **화음 누락의 93%(237)는 opening에서 사라진다.** 같은 단계에서 단일 머리는 0
- 「화음 · 검출」의 S4 소실 91은 머리 하나로는 opening에서 작아졌지만 **이웃 머리와 합친 성분**이 분할 경로로 들어가 살아난 것

| 화음 · 누락 · 선 위 · 오선 안 (72) | 0.89 / 0.89 | 0.89 / 0.88 | 0.95 / 0.89 | **0.32 / 0.51** |
| 화음 · 누락 · 칸 사이 · 덧줄 구역 (75) | 0.80 / 0.89 | 0.80 / 0.89 | 0.86 / 0.89 | **0.31 / 0.41** |
| 단일 · 검출 · 칸 사이 · 오선 안 (1065) | 0.95 / 0.90 | 0.95 / 0.90 | 1.04 / 0.90 | 1.03 / 0.89 |

(전체 표는 로그의 §2.) 차이는 **이미 S0에서** 난다(0.80~0.89 vs 0.95~1.01). 세로 메움(1 × 0.4sp)은 가로로 뚫린 구멍만 조금 메우고, 세로로 긴 구멍은 못 메운다.

## 3. 오선 · 덧줄 제거는 원인이 아니다

R 안 잉크 중 오선 제거 · 덧줄 제거가 지운 비율: 화음 누락 모든 위치에서 **중앙값 0 · 90% 지점 ≤0.04** — 단일 머리와 같다.
「두 머리 사이 오선 픽셀이 지워지며 갈라짐」 가설은 **틀렸다** — 오선 제거의 구제(두꺼운 열은 안 지움)가 화음 머리에서도 제대로 동작한다.

## 4. 이진화 구멍 (R 안: 원본 어두운 화소(흐림 뒤 gray < 128) 비율 → 이진화 잉크 비율, 중앙값)

| 글리프 | 화음 | 단일 |
|---|---|---|
| 꽉 찬 머리 `noteheads.s2` | 0.97 → **0.82** (n=430) | 0.96 → 0.91 (n=3981) |
| 빈 머리 `noteheads.s1` | 0.61 → 0.58 (79) | 0.59 → 0.57 (209) |
| 온음표 `noteheads.s0` | 0.47 → 0.45 (13) | 0.39 → 0.36 (13) |

꽉 찬 머리만, 그리고 **화음에서만** 이진화가 잉크를 크게 잃는다(-0.15 vs -0.05). 빈 머리는 원래 어두운 부분이 링뿐이라 거의 그대로다.
누락 254의 이웃 머리는 전부 위아래(3도 쌓임 — 2도 옆 0)다. 누락 254를 글리프별로는 세지 않았다. 그림의 빈 음표 화음(bbm5 (366,843) · (1373,1409))은 다른 경로(구멍 검출)의 누락이다.

## 5. 해상도 (같은 PDF를 dpi를 바꿔 렌더, `detect_noteheads` 원출력 기준 · 유령 필터 전)

| dpi | sp(px) | 화음 머리 누락 | 단일 머리 누락 |
|---:|---:|---|---|
| 177 (Aoharu와 같은 sp) | ≈11.5 | 43/522 (**8%**) | 126/4203 (3.0%) |
| 240 | ≈15.5 | 40/522 (**8%**) | 122/4203 (2.9%) |
| **300 (제품 기본)** | ≈19.5 | 268/522 (**51%**) | 95/4203 (2.3%) |
| 400 | ≈26 | 353/522 (**68%**) | 283/4203 (**6.7%**) |

- **해상도 차이가 맞다.** 창 25px ≈ 2.2sp(177dpi)면 쌓인 두 머리(≈1.9sp)가 창 안에 들어가 안 뚫리고, 300dpi(1.3sp)에서 뚫리기 시작하고,
  400dpi(0.96sp)에서는 **단일 머리까지** 뚫려 단일 누락도 는다 — 창/sp 비 하나로 세 결과가 다 설명된다
- **Aoharu(PNG, sp ≈11.5px)에 붙은 화음 누락이 없던 이유**: 창이 2.2sp라 뚫리지 않는다. Aoharu 골든 라벨 중 붙은 화음 모양으로 이웃한 라벨은
  24개(p2 18 · p3 6)다 — 정답이 없어 라벨로만 셌고, 「Aoharu 누락 0」은 **내가 따로 확인하지 않았다**
- 177 · 240dpi의 단일 누락이 300dpi보다 조금 많은 것은 다른 원인(작은 해상도에서 게이트 · 커널 반올림)으로 보이나 재지 않았다

## 6. 반사실 — 측정 안에서만 (`--binarize`)

`res.binary`에 원본의 확실히 어두운 화소(흐림 뒤 gray < 128)를 **더하기만** 하고(오선 · 보표는 그대로) `detect_noteheads`를 다시 돌렸다.

| 이진화 | 화음 누락 | 단일 누락 | 정답과 짝 없는 검출 |
|---|---|---|---:|
| 제품 | 268/522 | 95/4203 | 1786 |
| 어두운 화소 채움 | **31/522** | 82/4203 | 1605 |

- 화음 누락 **268 → 31**, 단일 누락도 95 → 82, 짝 없는 검출(유령 후보 · 꾸밈음 등 포함)도 1786 → 1605로 **줄었다**
- **이것은 방향 확인일 뿐 채택 근거가 아니다** — 유령 필터 전 원출력이고, 골든 711 · 20쪽 오삭제 · 최종 라벨 · 빈 음표 구멍 검출 · 임시표 · 오선 검출(이진화를 공유)은 재지 않았다

## 7. 수정 방향 후보 (구현 안 함 · 승인 대기)

1. **이진화 창을 sp에 비례**(예: 창 ≥ 2.5sp): 원인을 직접 고친다. 단 오선 간격은 이진화 **뒤에** 재므로 순서 문제가 있다 —
   1차 이진화로 sp를 잰 뒤 다시 이진화하거나, 창만 크게(예: 51px 고정) 해 본다. 이진화는 오선 검출 · 조표 · 임시표 · 사진 보정(`PHOTO_PREPROCESS.md`)이
   전부 공유하므로 **영향 범위가 가장 넓다**
2. **어두운 화소 보강**(반사실과 같은 것: `binary |= gray < T`): 적응형 이진화는 그대로 두고 전역으로 확실히 어두운 화소만 더한다. PDF · 스캔에선 단순하지만
   사진(조명 불균일)에서 그림자가 잉크로 들어올 위험 — 사진 경로는 제외하거나 따로 재야 한다
3. **음표 머리 검출에서만** 보강된 이진화를 쓴다: 오선 검출 · 기타 모듈은 제품 이진화를 그대로 쓰고 `detect_noteheads`에 넘기는 영상만 2번으로 바꾼다.
   영향 범위가 가장 좁다 — 단 빈 음표 구멍 검출도 같은 영상을 쓰므로 빈 음표 픽스처(PR #51)를 함께 재야 한다

어느 것이든 채택 전에: 골든 711 한 글자도 안 바뀌는지(Aoharu는 sp 11.5라 영향이 작을 것으로 예상하나 **확인 전**), 20쪽 오삭제 0, 새 유령 격자 육안, 빈 음표 픽스처,
사진 경로(A-8 계열). [B] 1단계의 「분할 뒤 제거 14」(B-2 · 보류)는 이것과 별개다.
