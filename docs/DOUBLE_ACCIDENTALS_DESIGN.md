# 겹임시표 정식 표기·재생 설계안 — 협의 전, 구현 없음

2026-10-16 Codex 제안. `modules/note_namer.py` 표기층과 피아노 재생의 계약을 정리한다. 인식·전파·문턱·JSON 규약은 바꾸지 않았다. CLI와 사용자의 합의 및 측정 전에는 제품에 넣지 않는다.

## 현재 구현에서 확인한 사실

- CLI의 `double_acc_suspects()`는 겹내림표 또는 겹올림표에 걸린 음표와 같은 마디 뒤 같은 음의 목록을 합쳐 돌려준다. 그 결과가 `double_acc` check가 된다. **두 종류와 직접/전파를 구분한 반환값이 아니다.** boolean 신호만으로 `bb`나 `##`를 선택하면 안 된다.
- `annotate_accidentals()`의 현재 유효 값은 `#`, `b`, `natural`, 빈 값이다. GUI·CLI는 그 배열을 `to_solfege_batch()`와 `build_document()`에 넘긴다. 현재 JSON의 pitch는 코드상 `D4`처럼 원음 글자·옥타브이고 임시표는 별도 필드다. pitch에 #을 덧붙이는 방식은 기존 재생기의 `[A-G][0-9]` 계약을 깨뜨린다.
- `note_namer.to_solfege()`는 고정도/영문에서 한 개짜리 #/b를 붙인다. 이동도는 실제 반음 높이로 계산한다. `label_audio.pitch_to_midi()`는 명시 임시표를 조표보다 우선하고, 사용자 수정은 표시 문구를 우선한다. 수정 문구의 연속 #/b는 이미 셀 수 있지만 자동 인식의 `accidental=bb/##`는 아직 지원하지 않는다.
- §1-40은 **확인 필요 표시만** 한다. 현재 `double_acc`의 검출률·헛표시를 정식 종류 판정의 정확도로 확대하지 않는다.

## 표기 제안

| 의미 | 내부 유효 값 제안 | 고정도 | 영문 | 자연음 대비 반음 |
|---|---|---|---|---:|
| 겹내림표 | `bb` | `레bb` | `Dbb` | -2 |
| 겹올림표 | `##` | `파##` | `F##` | +2 |
| 내림표 / 올림표 | 기존 `b` / `#` | 기존 유지 | 기존 유지 | -1 / +1 |
| 제자리표 | 기존 `natural` | 기호 없이 원음 | 기호 없이 원음 | 0 |
| 명시 임시표 없음 | 기존 빈 값 / JSON null | 조표 적용 | 조표 적용 | 조표 기준 |

ASCII `bb/##`를 제안한다. `x`·𝄪·𝄫를 출력하면 기존 입력·수정·글꼴 지원이 갈라지므로 정식 출력은 하나로 통일한다. 기호 자체를 입력 별칭으로 받을지는 별도 합의이며 이번 설계는 새 입력 문법을 추가하지 않는다. 원음 이름을 보존하여 `파##`를 `솔`로 임의로 바꾸지 않는다.

이동도는 기존 정책을 유지하는 안이다. 최종 음높이를 기존 `to_movable(letter, alteration, tonic)`으로 넘긴다. 다장조에서 Dbb는 도, F##는 솔이므로 고정도와 같은 `레bb/파##`를 억지로 만들지 않는다. 이동도에서도 원래 겹임시표 모양을 반드시 보여야 한다면 별도 표시 정책의 사용자 결정이 필요하다. 옥타브 옵션은 기존처럼 악보에 적힌 원음 옥타브를 붙이고 실제 소리 옥타브와 구분한다.

## CLI에 제안하는 인식 인터페이스

최소 변경안은 `annotate_accidentals()`의 기존 음표 순서/배열 길이를 유지한 채 **측정으로 종류가 확정된 곳만** `bb` 또는 `##`를 반환하도록 확장하는 것이다. 별도 겹임시표 참/거짓 목록을 표기층에서 재해석하지 않는다. 그 반환값은 자연음에 대한 최종 변화이며 조표 값에 더하는 값이 아니다.

- 직접 글리프에서 읽은 값과 마디 안에 이어진 값을 CLI 내부에서 구분한다. 뒤 음에 글리프가 없다는 이유로 값을 무효화하거나, 전파 값을 삭제 근거로 쓰지 않는다.
- 두 종류를 구분하지 못한 `double_acc`는 현재 값/표기와 check를 그대로 둔다. bb 또는 ##로 강제 승격하지 않는다. 사진 모드에서도 현재 미지원 경로를 임의로 켜지 않는다.
- 마디 경계·제자리표/단일 임시표에 의한 취소·동시 화음·다른 옥타브 전파 정책은 CLI가 기보 규칙과 실측을 보고 확정한다. Codex가 임의로 전파 규칙을 바꾸지 않는다.
- `double_acc` 사유는 종류를 알았다는 것과 별개다. 정식 표기를 넣는다고 check를 자동으로 없애지 않는다.

JSON에는 `accidental: bb/##`를 같은 뜻으로 남기고 pitch/좌표/원래 flags는 유지하는 안이다. 기존 스키마1의 허용 값 밖이고 구버전 표기·재생이 이를 조용히 오해할 수 있으므로, **제안은 스키마2로 올려 구버전이 거부하게 하는 것**이다. 새 버전은 스키마1을 읽고 기존 출력은 호환되게 지원한다. 이는 labels_io 소유자인 CLI 및 사용자 승인이 필요한 계약 변경이지 이번 문서로 확정한 규약이 아니다. 스키마 번호를 유지하는 대안은 구버전 오독 차단 방법까지 제시해야 한다.

## 피아노 음높이 제안

`midi = 12 * (octave + 1) + 자연음 반음값 + 적용 변화량`을 유지하고 bb=-2, ##=+2만 추가한다. 명시 임시표가 있으면 조표에 더하지 않고 대신 쓴다. 제자리표는 0, 명시 값이 없으면 조표를 적용한다. 12음 안에서 먼저 나머지 연산을 하지 않아 옥타브 경계를 보존한다. 0~127 밖은 기존처럼 재생하지 않고 이유를 남긴다.

| 원음·유효 임시표 | MIDI | 실제 소리 |
|---|---:|---|
| D4 + bb | 60 | C4 |
| F4 + ## | 67 | G4 |
| B4 + ## | 73 | C#5 |
| C4 + bb | 58 | Bb3 |
| D4 + bb, 조표에서 D에 b | 60 | 조표 b를 또 더하지 않음 |
| F4 + natural, 조표에서 F에 # | 65 | F4 |

기존 피아노 음색·WAV 길이·리듬·그룹 묶음은 바꿀 이유가 없다. 사용자 수정 「레bb/파##」는 현재처럼 수정 문구를 우선하고, 원래 자동 인식 값과 flags는 JSON/수정 기록에 남긴다. 해석 불가능한 수정 문구는 추측해 재생하지 않는다. 확인 필요 제외 옵션은 그대로 유지한다.

단일 #/b/natural/빈 값의 기존 출력 바이트0, 겹표기 직접/전파·취소 구간, 한 칸 조표와 겹임시표의 비합산, 옥타브 경계, 수정 문구 우선, 구스키마 읽기/신스키마 구버전 거부를 검사한다. CLI는 종류별 정답 분포와 겹침을 먼저 확인한다. 그 뒤 전체검사·골든711·PDF17·쪽별 좌표/음고/표기·오삭제0을 확인한다. 표기·확신도만 고치는 단계와 판정/재생 단계는 분리해 비교한다.

**협의 요청:** CLI가 종류가 확인된 bb/##를 기존 배열로 넘길 수 있는지, 현재 boolean 표시가 어디까지 확정 정보를 제공하는지, 전파·취소를 어떤 범위로 지원할지와 스키마2 전환안에 답해 주기 바란다. 지금 진행 중인 조바꿈 측정이 끝난 뒤 협의하며, 이번에 추가 측정을 요청하거나 실행하지 않는다.
