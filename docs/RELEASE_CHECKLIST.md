## 2. 기준과 빌드 기록

저장소 루트의 PowerShell에서 실행한다. **아래 명령은 임시표 수정 검증 후에만 실행한다.**

```powershell
$env:PYTHONIOENCODING = 'utf-8'
git rev-parse HEAD
git status --porcelain
venv\Scripts\python.exe tests/run_all.py
venv\Scripts\python.exe build.py
```

`git status` 출력이 있으면 정리 후 새 기준으로 시작한다. 배포 때 `--allow-dirty`를 쓰지 않는다.
`build.py`는 원본 spec으로 빌드하고, 전체 검사·라이선스 고지·PDF 관련 라이브러리
제외·빌드 중 소스 변경 여부를 확인한 뒤 ZIP을 만든다. 수작업으로 spec을 바꾸거나
직접 PyInstaller 옵션을 조합하지 않는다.

| 기록 항목 | 값 |
|---|---|
| 검증자·날짜·Windows 버전 | 미실행 |
| 실제 전체 커밋 SHA / 브랜치 | 미정 |
| 임시표 복구 수 / 새 오삭제 / 유령 변화 / 예상 실패 수 | 미검증 |
| 빌드 명령·종료 코드 | 미실행 |
| `dist/<태그>/build-info.json` | 미생성 |
| `debug/build-pipeline/<태그>/build.log`·`tests.log` | 미생성 |
| ZIP 경로 / ZIP SHA-256 | 미생성 |
| exe SHA-256 / `dirty=false`확인 | 미생성 |

실행 후 `build-info.json`의 commit이 위 실제 SHA와 같은지 확인한다.
exe 해시는 `Get-FileHash -Algorithm SHA256 -LiteralPath '<exe 경로>'`로,
ZIP 해시는 같은 명령에 ZIP 경로를 넣어 기록한다. build-info에는 **exe 해시**가 들어 있다.
build-info 자체만으로 배포자의 신원을 확인한 것으로 취급하지 않는다.

## 3. 소스와 exe 결과 비교

- [ ] 같은 PC·같은 폰트·같은 원본 PNG/JPG를 사용한다. PDF와 이미지의 결과를 서로 비교하지 않는다.
- [ ] RE:Aoharu 1쪽과 쇼팽 D♭ 1쪽을 최소 표본으로 준비하고 입력 파일 해시를 기록한다.
  PDF에서 꺼낸 이미지는 한 번만 만들고 같은 파일을 양쪽에 준다.
- [ ] 같은 커밋의 `venv\Scripts\python.exe gui.py`와 배포 exe를 **차례로** 실행한다.
- [ ] 음자리표 자동, 고정도, 조성 입력 없음, 맑은 고딕,18pt,`#dc1414`를 동일하게 설정한다.
  두 실행 사이 입력·설정을 바꾸지 않는다.
- [ ] 소스와 exe의 결과 PNG·라벨 JSON·줄 수·확실/주의/의심 수·화면을 별도 폴더에 보존한다.
- [ ] PNG를 디코딩한 픽셀 배열의 크기와 값이 완전히 같다. PNG 파일 해시만 비교하지 않는다.

예: Python 실행 환경에서 실제 두 결과 경로를 넣는다.

```powershell
venv\Scripts\python.exe -c "from PIL import Image; import numpy as np; a=np.array(Image.open(r'<소스 결과 PNG>').convert('RGB')); b=np.array(Image.open(r'<exe 결과 PNG>').convert('RGB')); assert a.shape==b.shape and np.array_equal(a,b), '소스/exe 픽셀 불일치'; print('픽셀 동일')"
```

차이가 나면 원본 해시·설정·폰트·커밋부터 확인한다. 차이를 없애려고 판정 코드나 골든을 바꾸지 않는다.

## 4. 확신도·JSON 저장·재렌더링

- [ ] 보통/연한/주황 점선이 실제 결과에 보이고 원본 음표와 대응한다.
- [ ] JSON의 `confidence` 값과 화면의 확실·주의·의심 수, 주황 점선 위치가 맞는다.
  어떤 단계의 표본이 없으면 “해당 표본 없음”으로 적고 표시가 검증됐다고 하지 않는다.
- [ ] `output/<이름>_라벨.json`이 생성되고 JSON을 읽을 수 있다. 이미지와 같은 입력의 파일인지 확인한다.
- [ ] exe가 만든 JSON을 같은 입력 이미지에 재렌더링한다. 현재 exe는 GUI 진입점이므로
  `--relabel` 검증은 **소스 CLI**로 한다. exe에 없는 명령행 기능을 있다고 기록하지 않는다.

```powershell
venv\Scripts\python.exe main.py '<동일 원본 PNG>' --relabel '<exe가 만든 라벨 JSON>' --output-dir output/release-relabel --font-size 18 --color '#dc1414'
```

- [ ] 재렌더링 PNG와 원래 exe PNG의 픽셀이 같다(앞 절의 비교 명령 사용).
- [ ] JSON **사본**의 라벨 text 하나를 바꿔 다시 그렸을 때 그 수정이 반영된다.
  기준 JSON과 골든은 편집하지 않는다.
- [ ] 다른 원본 이미지에 그 JSON을 얹으면 재렌더링이 중단된다.
- [ ] 주황 점선이 없는 오류도 있을 수 있다는 안내가 문서에 남아 있다.

## 5. 깨끗한 환경·첫 실행

다른 일반 사용자 계정 또는 **처음 만든 새 폴더**에 최종 ZIP을 풀어 확인한다.
새 폴더 검사는 설정 독립성 확인일 뿐 새 PC 검증과 같지는 않다.
가능하면 Python을 따로 설치하지 않은 Windows 사용자 환경에서도 확인한다.

- [ ] ZIP 안 파일이 아래5개뿐이다. 폴더 중첩·개인 악보·venv·settings·output이 들어 있지 않다.
  `악보헬퍼.exe`, `build-info.json`, `먼저 읽어주세요.txt`, `LICENSE`, `THIRD_PARTY_NOTICES.txt`.
- [ ] ZIP 밖으로 압축을 완전히 풀었다. 첫 실행 전에 `settings.json`과 `output`이 없다.
- [ ] 실행 창·아이콘·기본 설정이 정상이다. 개인 폰트·개발 폴더를 요구하지 않는다.
- [ ] PNG/JPG를 처리하면 **exe 옆** output이 생기고 결과 PNG와 JSON이 들어간다.
- [ ] 설정 하나를 바꾸면 exe 옆 settings.json에 저장되고 종료·재실행 뒤 유지된다.
- [ ] 한글·공백이 있는 새 폴더에서도 같은 결과가 나온다.
- [ ] 원본 선택에서 PDF를 지원하는 것처럼 보이지 않는다.
- [ ] “악보 줄 N개를 찾았습니다”를 읽을 수 있고 실제 줄 수와 대조했다.

ZIP 파일 목록은 `venv\Scripts\python.exe -m zipfile -l '<최종 ZIP>'`로 기록한다.
기존 settings/output을 지워 깨끗하게 만들기보다 새 폴더를 사용해 개인 자료를 보존한다.

## 6. SmartScreen 안내와 전달

- [ ] 실제 전달 경로에서 받은 ZIP을 새 환경에서 실행해 경고 유무·문구를 기록한다.
  로컬에서 만든 exe 실행만으로 다운로드 후 경고를 검증했다고 하지 않는다.
- [ ] 배포자가 안내한 다운로드 출처와 별도로 공개한 ZIP 해시를 확인할 수 있다.
- [ ] “추가 정보 → 실행”이 보이는 경우의 안내가 실제 화면과 맞는다.
  실행 선택지가 없으면 보안 기능을 끄거나 우회하지 않고 관리자에게 확인한다.
- [ ] Defender/SmartScreen을 끄라는 문구가 없다.
- [ ] 최종 ZIP5개 파일을 함께 전달한다. exe만 따로 보내지 않는다.

각 항목에 실행 환경·결과 파일·로그 또는 화면 근거를 연결한 뒤 배포 판단을 남긴다.
지금 이 문서의 체크 항목은 모두 **미실행**이다. 자동 빌드 성공만으로 이 점검표를 통과한 것이 아니다.


## 실제 클릭 확인 (소스 GUI·배포 exe)

- 마우스 입력은 다른 측정/GUI 검사와 동시에 하지 않는다. 검사 전 사용 가능한 메모리와 CLI 프로세스를 확인한다.
- 소스 GUI: `python tests/check_gui_native_click.py`를 대화형 데스크톱에서 단독 실행한다. 자체 생성 작은 이미지로 「계이름 달기」「다음 쪽」「다음 확인 필요」 실제 SendInput 입력과 상태 변화를 확인한다. 입력칸/버튼 콜백을 직접 호출하는 기존 단위 검사와 구분한다.
- 배포 exe: 격리 사본의 SHA-256을 기록하고, 두 이미지 선택·변환 후 위 세 버튼을 실제 클릭한다. 쪽 번호와 현재 확인 라벨이 바뀌는 화면을 남긴다. `python tests/_native_click.py --hwnd <최상위창> --pid <검사exe PID> --x <화면x> --y <화면y>`는 클릭 직전 좌표 소유권이 일치할 때만 입력한다. 창 좌표는 매번 다시 재고 옛 좌표를 그대로 쓰지 않는다.
- 다른 창이 가렸거나 최소화된 경우는 입력하지 않는다. 환경 실패/미확인으로 기록하고, 콜백 직접 호출이나 소스 검사 성공으로 exe를 통과 처리하지 않는다.
- 실제 클릭 검사는 사용자의 커서를 움직이므로 기본 `run_all.py`의 파일 목록 밖에서 명시적으로 실행한다. 전체 검사 통과와 실제 클릭 통과를 각각 기록한다.

- 검사 사본 exe는 완료·실패와 관계없이 종료하고, 원래 사용자 앱은 건드리지 않는다. 실제 커서 위치와 요청 좌표가 다르면 입력하지 않는다.

- 단축키 소스 실제 입력: `python tests/check_gui_native_shortcuts.py`를 단독 실행한다. 영문/한글 IME × NumLock ON/OFF에서 N→N→P와 F1, 입력칸에서 N/P 순회 금지, N을 누른 채 다른 키를 누를 때 오인하지 않는지 확인한다. 키마다 실제 전면창/PID·Tk 포커스·IME 상태를 기록하고 원래 키보드 상태로 복원한다.
- 새 exe에도 위 네 조건을 실제 SendInput으로 확인한다. frozen exe에서 Tk 내부 포커스를 직접 조회할 수 없으면 OS 포커스 기록과 소스 추적을 구분한다. 소스 성공을 새 exe 성공으로 쓰지 않는다.
