# C-11: ♭ 조표 판정의 부분화소 위상 민감도

> 2026-10-02 현재 상태: 조표 제품 수정은 PR #136으로 main에 병합됐다. 아래 2026-09 측정·기각 전 상태는 당시 제품의 역사 기록이며 현재 실패나 빌드 보류 지시가 아니다. 수정 근거·검증 범위는 [KEYSIG_VOTE_FIX](KEYSIG_VOTE_FIX.md), 사진 M1 구현은 PR #83을 참조한다. 과거 압축 원자료는 재생성하지 않았다.

2026-09-18 정정. 제품 미수정. 먼저 복구 업로드(e14f808)를 끝낸 뒤 사용자가 전달한 Claude 측정을 반영했다. 153조건의 누락 gzip을 한 번 재생성한 것 외에 정밀 격자·dpi 측정은 다시 실행하지 않았다.

## 관측 범위

- 바흐는 x 0.36~0.60의 0.02 간격 표본 13개 모두 실패한다. 이를 연속 실패 대역으로 보고했으나 실수 축의 모든 값을 증명한 것은 아니다. y −0.25/+0.75도 실패한다.
- D♭·G♭은 x −1~1, 간격0.05의 각 41조건 중16조건(39%) 실패한다. −0.40~−0.05, +0.60~+0.95 대역이다. 0.25 격자의 6실패만으로 범위를 제한하지 않는다.
- 아래 막대 수는 **보표당 최대 막대 수**다. 이전 Codex 표의 **합의 클러스터 수**와 같지 않다. 표에 나온 +1을 조표 정답에 그대로 더하거나 두 집계를 섞지 않는다.

| 조표 | 300dpi 원본 최대 막대 | x −0.25/+0.75 | 최종 출력과 해석 |
|---|---:|---:|---|
| ♭1 | 2 | 2 | ♭1. 막대 증가 없음, 이유 미확인 |
| ♭2 | 3 | 4 | ♭2. n_holes 제한이 과계수를 가림 |
| ♭3 | 4 | 5 | ♭3. 같은 제한 |
| ♭4 | 5 | 6 | ♭4. 같은 제한 |
| ♭5 | 6 | 7 | ♭6 오판 |
| ♭6 | 7 | 8 | ♭7 오판 |
| ♭7 | 8 | 9 | ♭7. 7개 상한이 과계수를 가림 |
| ♯1 | 2 | 3 | ♯1. singles가 ♯ 개수에 들어가지 않음 |

따라서 ♭1~4·♭7의 최종 정답 일치만으로 내부 귀속이 옳다고 하지 않는다. 다만 **♭1은 이 표에서 증가하지 않았으므로 n_holes가 증가를 가렸다고 단정하지 않는다.** 증가가 가려진 플랫 표본은 ♭2·3·4·7이며, ♭ 전체를 수정·검증 범위에 포함한다. 원본의 정확한 출처와 기존 한계는 [153조건 측정](KEYSIG_SUBPIXEL_CONTROLS.md)에 있다.

## 코드에서 확인한 비대칭과 다음 조건안

`_vote_key_signature`의 ♯ 분기는 간격 0.3~0.55sp와 `_same_glyph`를 통과한 pairs의 사슬로 개수를 정한다. singles는 그 개수에 쓰지 않는다. ♭ 분기는 `min(len(singles), n_holes)`이며 같은 ♭에 속하는 복수 singles를 합치는 대응 검사가 없다. 보간으로 기둥/배가 분리되어 독립 후보로 들어가는 경로와 부합한다.

이 구조는 **추가 singles가 이미 성립한 ♯ 쌍을 해치지 않은 사례**를 설명한다. 모든 재표본화에서 ♯이 안전하다는 증명은 아니다. 기존 Aoharu의 ♯ 막대 탈락·♭ 전환은 별도 회귀 대상에 남긴다.

다음 제안은 ♭별 잉크 귀속을 확인해 같은 글리프에서 나온 singles를 합친 뒤 세는 것이다. `_same_glyph`의 1.75를 그대로 재사용하지 않는다. 새로운 제품 조건은 아직 없다.

- 원본에서 먼저 고른 ♭1~7의 기둥/배와 서로 다른 이웃 ♭, 음표 기둥을 각각 표시한다. 같은 글리프 내부 쌍과 서로 다른 글리프 쌍의 y 간격·범위 및 sp 정규화 분포를 별도로 기록한다.
- 보간으로 분리된 가짜 중복도 **같은 ♭ 내부**일 수 있다. 정상 기둥/배와 그 중복을 서로 다른 정답 클래스로 놓아 억지로 분리하지 않는다. 합쳐야 하는 동일 글리프와 합치면 안 되는 이웃 글리프를 대조해야 한다.
- raw/closing 전후를 따로 보며, 연결 성분이 음표·이웃 기호까지 붙잡는 반례와 다른 폰트·실제 악보 여러 쪽을 포함한다. 분포가 겹치면 단일 y 문턱을 채택하지 않는다.
- 클러스터 폭3px·높이 상한·투표선 조정, n_holes 의존, 재표본화를 추가하는 전체 정규화는 채택하지 않는다. 좌표를 sp로 나누는 것 자체와 영상 재표본화도 구분한다.

## dpi와 채택 검증

Claude 원자료의 바흐 x 0~1, 간격0.05 결과:

| dpi | 조표 불일치 / 전체 | 예외 |
|---|---:|---:|
| 150 | 8/21 | 0 |
| 200 | 11/21 | 0 |
| 250 | 11/21 | 0 |
| 299 | 17/21 | 0 |
| 300 | 5/21 | 0 |
| 400 | 5/21 | 0 |
| 600 | 3/21 | 14 |

5/21은 약23.8%다. 600dpi의 14예외를 성공에 포함하지 않는다. 실행 성공7개 중3개도 오판이다. 어느 dpi가 안전하다는 문턱을 만들지 않는다.

채택 조건1~4는 기존 측정 문서 그대로 유지하고, 5~11을 그 문서에 추가했다. 원시 막대·합의 클러스터·글리프별 귀속·최종 조표를 함께 남기며, 안전망 해제는 **측정용 대조**에서만 한다. 내부 검증을 추가해도 최종 음표·계이름 검증을 생략하지 않는다. C-11을 해결하기 전에 재표본화를 일으키는 C-10 보정을 먼저 넣지 않는다.

## 협업 분담과 남은 것

- C-11 개발·측정 도구는 Codex, 독립 검증은 Claude CLI다. 제안 단계와 채택을 분리한다.
- `Staff`의 보표별 x 범위 공개 API는 **Codex가 담당**한다(사용자가 이번 안정화 개발 소유권을 해제한 범위). C-11 뒤 C-10 착수 때 범위 정의·측정 근거·내부 휨 잔차와 함께 제시한다. 이번에는 preprocess.py를 수정하지 않았다. 영상 폭을 실제 오선 길이로 가장하지 않는다.
- renderer 소유권은 COLLAB의 Claude 이관과 AGENTS/CLAUDE의 Codex 표기가 충돌한다. 최신 이관 기록에 따라 작업을 보류하고 사람의 규약 정정 승인 대상으로 남긴다. 규약은 수정하지 않았다.
- 임시표 직접오인식/전파와 빈 머리 가림 손실은 별개이며, C-11 완료로 함께 해결됐다고 하지 않는다. exe 빌드 보류를 유지한다.
