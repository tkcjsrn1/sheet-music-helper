※ 원본 크기 이진화의 음고 오류 20개는 확대 확인을 안 했다(머리 절반 이상을 놓친 입력이라 판정 대상에서 뺐다).

- **「Audiveris는 캡처 이미지를 처리하지 못한다」는 성립하지 않는다.** 원본 RGB 파일에서만 실패했고, **같은 크기 그레이스케일로 저장만 해도 처리된다**
- 처리된 가장 좋은 조건(2배, 컬러·그레이)에서 Audiveris는 **오삭제 11.5% · 유령 0 · 음고 오류 1**. 이 쪽에서 악보헬퍼(0/0/0)가 오삭제는 적지만, 차이는 「처리 실패 대 성공」이 아니라 **오삭제 26 대 0**이다
- Audiveris 오삭제는 원본 크기 그레이스케일 28개를 전부 확대해 봤다 — **세로로 쌓인 온음표 화음의 머리**(한 머리만 잡고 나머지를 놓침)다. 유령은 모든 조건에서 0
- 음고 오류 1(2배): 낮은음자리표 위 덧줄에 쌓인 A4·D4 2분음표에서 D4를 위쪽 보표에 붙여 E3로 읽었다 — 원자료 확인
- 대조: 정답은 골든 라벨 226개(전수 판정 + 음표 쪽 확인). 확대 입력은 좌표를 배율로 나눠 되돌렸고, Audiveris 보표 번호는 **그 번호 머리들의 중앙 y에 가장 가까운 우리 보표**로 대응시켰다(순번 대응은 입력에 따라 밀렸다)

## 2. 대조 방법

- **정답**: `tools/measure_omission_rate.py`와 같다 — PDF 음표 머리 글리프, 같은 자리 겹친 글리프·다른 크기 머리 제외 → 239개
- **Audiveris 출력**: D♭ 1쪽은 PR #59가 남긴 `omr_feasibility/heads.tsv`·`chopin_Db_p1.mxl`. 바흐·B♭m 1쪽은 **같은 설치본(MSI SHA-256 `5f1b4e96…` 일치)·같은 명령**(`-batch -transcribe -export -save`)으로 CLI가 돌렸다. 입력은 PR #59처럼 `load_image(pdf_page=0)` 300dpi 한 번 렌더, 보정 없음. 종료 코드 0, 머리·음 목록은 `tools/export_audiveris_notes.py`로 `omr_feasibility/bach_p1/`·`chopin_Bbm_p1/`에 추출
- **좌표**: Audiveris 입력이 우리와 같은 300dpi 렌더라 `heads.tsv`의 x/y/w/h 중심을 그대로 썼다.
  **확인** — 세 쪽 모두 중앙 어긋남 0.5px 미만(D♭ −0.42/0.21 · 바흐 0.09/0.16 · B♭m −0.12/0.10)
- **짝짓기**: 우리 측정과 같다 — 가까운 쌍부터 1:1, 가로 0.7sp · 세로 0.5sp
- **음고**: `relative_pitch`(가운데 줄 0, 위가 음수, 반칸) → 맨 아랫줄 기준 반칸 `4 − rp`, 음자리표는 **MusicXML의 음자리표**
  (보표 1 = G2 높은음, 보표 2 = F4 낮은음). 세 쪽 짝지은 쌍 전부 반칸 위치가 정답과 일치해 부호 규약을 확인했다. **곡 중간 음자리표 변경에 흔들리지 않도록 머리 위치 음고는 PDF 음자리표로 계산**하고, Audiveris의 음자리표 판독은 MusicXML 묶음 비교로 따로 본다
- **MusicXML 교차 확인**: 좌표가 없어 개별 대응은 못 한다. 대신 음이름+옥타브 **묶음**을 비교했다 —
  D♭ 1쪽은 꾸밈음 크기 4개를 빼면 같고, 바흐는 정확히 같고, B♭m 1쪽은 성부 공유 G5 1개와 8va 구간 2개(옥타브) 말고 같다. 묶음 비교라 두 음이 서로 뒤바뀐 경우는 못 잡는다
- **대조 불가로 따로 센 것**: 다른 크기 머리(꾸밈음·빠르기 표시)에 붙은 결과 — 양쪽 다 오삭제·유령에 안 넣었다

## 3. 비교하지 않은 것

- **임시표(♯·♭·♮)와 최종 표기** — 양쪽 다 음이름+옥타브만 비교했다
- 리듬·성부·박자 — 악보헬퍼는 계이름만 다루므로 비교 대상이 아니다
- Audiveris는 문자 인식 언어 없이 돌렸다(PR #59). **모든 기능이 구성된 비교 환경이 아니다**
- PDF 세 쪽은 보정 없이 원본 렌더를 양쪽에 넣었다. RE:Aoharu는 §1-1에서 Audiveris에만 확대·그레이스케일·이진화를 줘 봤다(악보헬퍼는 원본 그대로)

## 4. 이 비교에서 말할 수 있는 것

- 인쇄 PDF 300dpi(LilyPond) 세 쪽에서 **Audiveris는 머리 검출·음고 위치가 정답과 완전히 일치했다.** 악보헬퍼는 붙은 화음 쪽에서 오삭제 10.0%·음고 오류 4.2%, 세 쪽 모두 유령 8~16개
- 화면 캡처 한 쪽에서, 원본 그대로면 Audiveris는 결과를 못 냈지만 **그레이스케일로 저장만 하면 처리됐고 쌓인 온음표 화음에서 11.5~12.4%를 놓쳤다.** 악보헬퍼는 오류 0
- 두 쪽의 조건이 달라 도구 우열을 일반화할 수 없다. 같은 조건의 여러 쪽이 필요하다
