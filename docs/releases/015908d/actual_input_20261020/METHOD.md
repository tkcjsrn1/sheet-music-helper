# 실제 입력 방법·범위·중간 시도

015908d ZIP 사본의 SHA를 확인하고 ctypes SendInput·SetCursorPos를 사용했다. 입력 전 검사 사본 실행 경로/PID와 WindowFromPoint의 최상위 창을 확인했다. 소스 콜백 호출이나 직접 MIDI 함수 호출을 실제 GUI 입력으로 세지 않았다. 매 세션 HEAVY.lock 원자 취득, finally 사본 종료·IME/NumLock 복원·본인 잠금 해제를 적용했다. CLI 쉼표 holdout 잠금 때 대기했다.

두 이미지 변환에서 2쪽 처리 중 비활성 → 활성 복원을 연속 캡처했다. 활성 관찰 후 클릭까지 10.90ms(도구 관찰/입력 시간)이며 결과는 2/2·chopin_Db_p1이다. 한글 N/N/P의 표시 순서 1/2/1, NumLock OFF 영문 F1의 다른 핸들 도움말 새 창을 확인했다.

둘째 쪽 B3 시b를 도#로 수정해 자동 저장 → 앱 종료(기존 창 없음) → 다른 PID로 새로 실행 → 수정본 폴더·해시가 같은 원본 선택 → 수정 유지 및 되돌리기(시b·원래 check 사유·선택 복원)를 확인했다. 별도 내보내기 창은 취소했고 실제 자동 저장된 수정본으로 검증했다.

레bb는 검출 음을 사용자 표기로 고친 사례다. 자동 검출 레bb를 찾았다는 뜻은 아니다. F5 자리에 레bb를 저장하고 단일음 영역을 드래그 선택해 MIDI72/C5를 확인했다. 실악보 Clara2 Bravura (679,717) F4 파##는 자동 검출값 그대로 check·edited=false를 유지한 한 라벨의 영역 JSON 저장·수정 창 선택·MIDI67/G4 출력을 확인했다. 확인 필요 음 제외 옵션만 끄고 들었고 인식 설정은 바꾸지 않았다.

기본 출력 WASAPI만 녹음하고 마이크는 쓰지 않았다. 두 단일음에서 예상 기본음과 3개 이상 정수배 배음을 확인했다. 음이 있는 구간의 수집 버퍼는 각0.42초다(6초 감시 전체를 연속 녹음한 길이가 아님). 스피커 청취/음질 평가는 별도다. 피아노는 제품의 GM Acoustic Grand Piano 경로다.

GUI와 CLI 원래 변환 JSON의 라벨·좌표·음고·보표·원본·나머지 문맥은 일치했다. music.notation만 GUI solfege-fixed / CLI solfege로 달랐다. note_namer.to_solfege의 기존 고정도 별칭이며 원문을 수정하지 않고 gui-cli-equality.json에 차이를 기록했다. 이 교차 비교를 전체 JSON 바이트 같음으로 보고하지 않는다. 기존 자동 소스/exe selftest 경로의 12쪽 원문 바이트 일치는 별도로 유지한다.

중간 도구 시도: 두 helper의 SendInput ctypes 형식 충돌, 콘솔에 가려진 좌표 입력 차단, 변환 버튼 배경색으로 완료를 추정한 오류가 있었다. 앱 코드는 바꾸지 않고 전면 창·실제 버튼 글씨 복원·Canvas geometry·저장 완료를 기다리도록 도구만 보완했다. 최초 전체 재생 녹음은 무음이었다. 원인은 단정하지 않으며 이후 전면 확인·단일음 실제 입력에서 출력 재현에 성공했다. 높은 G5의 사용자 편집 파##도 출력은 있었으나 5% 이상 배음3개 조건을 충족하지 못했다. 기준을 낮추지 않고 실악보 F4/G4를 따로 검증했다. 중간 원자료는 F:에 보존하며 성공 자료와 섞지 않는다.
