# #373·#374 최종 베타 준비

CLI #375의 실제 대기 신호와 사용자의 단독 시간창 확인 뒤 진행한다. #374는 CLI가 이미 main에 병합했으며 Codex가 판정/골든 파일을 편집하거나 해당 PR을 병합하지 않았다. #373의 기본 변경은 포커스 확인 검사 재사용과 실패 stderr 원문 보존이다.

#366·#368 당시 strict8 → #374의 새 strict8 전후 전체 자료는 strict-before-after.json.gz에 보존한다. 8입력 전체에서 라벨 수/순서/음고/좌표/표기/문맥 변화0. D♭ 1쪽7곳의 double_acc와 certain→check 외 변화0. Aoharu3쪽 전체JSON 변화0. 제품·자산 SHA는 source-identity.json에 있다.

selftest D♭ 원문은 SELFTEST_DB_CHANGES.json.gz에 전후/SHA와 함께 보존했다. 해당7행만 confidence/check·double_acc로 바뀌고 나머지255행 및 문맥/순서가 같다. CLI가 병합한 PDF스냅샷의 전행과 일치하며 Aoharu 기준은 그대로다. 처음에는 snapshot diff 줄 수에서8곳으로 잘못 가정해 적용 전 단언에서 중단했다. 실제 JSON 전행 비교로7곳임을 확인했고 기준을 그대로 소스 출력과 일치시켰다. 스냅샷/정답골든을 수정하지 않았다.

읽기 검토에서도 사유/확신도7곳 외 변화0·기준 완화0을 확인했다. 안내문에는 겹임시표를 아직 정확히 읽지 못하며 확인 필요로 표시될 수 있다는 문장만 넣는다. 정식 겹표기/음높이 재생 변경은 이번 범위에서 구현하지 않는다. GUI는 confidence에 따라 표시·개수·순회를 하므로 새 사유 사전이 필요 없다.

현재 최신 전체검사 실행 중이다. 앞의 구버전 검사는 main에 #374가 추가돼 본인 트리만 중단했으며 통과로 세지 않는다. 전체검사/원격 녹색 전 #373을 병합하지 않는다. 최종 빌드/실제exe 검증 완료 전 de4b88e를 최종으로 승격하지 않는다.
