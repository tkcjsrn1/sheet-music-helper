# 임시표 직접 오인식: 가로 연결 지표 기각과 다음 후보

2026-09-14. **제안이며 제품 조건 미채택.** 개발 Codex, 독립 측정·검증 Claude CLI.
임시표·음표 검출·삭제 판정 코드는 이번 작업에서 바꾸지 않는다.

## 기각을 확정한 근거

Claude CLI `2da52a1`의 `docs/ACCIDENTAL_GHOST_MEASURE.md` §13을 기준으로 한다.
[독립 검증 원문](https://github.com/tkcjsrn1/sheet-music-helper/blob/2da52a1/docs/ACCIDENTAL_GHOST_MEASURE.md).

- 170개 지표는 독립 재현됐지만, 구간 수는 실제 가로획 수가 아니다.
- 진짜 임시표 7개가 3구간, 진짜 ♮ `(1126,1630)`·`(1723,2372)`이 1구간이다.
- `==2`는 이런 진짜 기호를 놓친다. `>=2`도 1구간 진짜 둘을 놓치면서
  화음 덩어리 `(1623,2144)`를 통과시킨다. 문턱을 움직여 해결하지 않는다.
- closing에서 기존 대조군 16개가 보존됐다는 것은 그 표본 내 관측이다.
  옆 잉크로 인한 추가 연결을 막지 못하므로 다른 단계와의 단순 조합도 채택하지 않는다.
- 국소 기울기 0.3~2.0°에서 대조군 지표가 유지됐다. 이것을 페이지 전체 오선 검출의
  회전 안정성으로 확장하지 않는다. 국소 막대 간격과 페이지 오선 길이는 규모가 다르다.
- 미판정 144개 중 구간 수가 2가 아닌 23개만 전수 육안 확인됐다.
  나머지 121개의 정상 여부는 전수 확정되지 않았다.
- 음표 창 밖 `(1443,2384)` ♮ 등 실제 정상 임시표가 발견됐다. 검출된 음표의 창만
  훑는 방식은 대조군 자체를 누락시킨다. 실제 임시표 촬영본은 여전히 미검증이다.

가로 연결 수를 확정 판정이나 가중 점수의 근거로 재활용하지 않는다.
단순 연결 성분 공유, closing 추가량, filled 일괄 구제, 구멍 부재에 의한 삭제도
기존 반례를 해결한 근거 없이 다시 채택하지 않는다.

## 다음 후보: 완전한 글리프의 위치 증거와 음표 후보의 귀속을 분리

제안하는 삭제 조건은 다음 세 가지를 **모두** 만족하는 경우다.

1. **직접 관측한 임시표 글리프 인스턴스가 있다.** 종류뿐 아니라 원본 좌표와 이를
   설명하는 잉크 영역을 가진다. 마디 내 전파로 얻은 임시표 값은 이 증거가 아니다.
2. **삭제 후보의 머리처럼 보이는 덩어리가 그 글리프의 일부로 설명된다.**
   단지 다른 음표 왼쪽 창에 들어간다는 이유로 지우지 않는다. 글리프 전체가 차지한
   연결 성분이나 사각형 전체를 증거 영역으로 간주하지 않는다. 옆 음표가 붙을 수 있다.
3. **같은 잉크를 진짜 음표로 해석하는 충돌이 해결됐다.** 실제 음표 머리·기둥 또는
   빈 머리의 독립적인 해석이 남으면 삭제를 보류하고 후보를 보존한다.
   음표 검출 실패나 구멍이 없다는 사실만으로 충돌이 없다고 판단하지 않는다.

이 세 가지는 안전 요구사항이다. 1·2·3을 판정할 측정법은 아직 통과하지 않았으며
이 문장만으로 바로 구현하거나 정상 삭제가 보장된다고 주장하지 않는다.
전파 구분만 넣어서 돌아오는 기존 유령 3곳도 해결해야 한다.

## 무엇을 다르게 측정할 것인가

**가로 구간 수 대신 글리프 전체의 2차원 모양과 이웃 도형의 경쟁 해석을 비교한다.**
첫 실험 후보는 확인된 ♯·♮·♭ 형태와 음표 머리+기둥 형태의 국소 정합이다.

- 음표를 기준으로 자르기 전에 보표 밴드에서 후보 위치를 모은다. 원본에서 사람이
  고른 정상 기호도 대조군에 추가하여 밴드 검출기가 놓친 사례까지 센다.
- 실제 검증 크롭과 별도 조판의 글리프를 모델 후보로 삼고, 원본·오선 제거·closing의
  픽셀 출처를 보존한다. 한 모델/한 조판의 일치만으로 일반화하지 않는다.
- 글리프 모양에 대응된 잉크, 맞지 않는 잉크, 복원으로 추가된 잉크를 분리 기록한다.
  추가 잉크나 잔여 잉크가 있다는 사실 자체를 참/거짓 규칙으로 삼지 않는다.
- 같은 패치에 대해 「기호 하나」와 「음표+기둥/다른 기호의 획」 해석을 함께 놓는다.
  공유 연결 성분 하나에서 어떤 부분이 각 해석에 속하는지 표시한다.
  정합 점수 차이를 쓸 경우 정상/오류 분포와 쪽별 반례를 먼저 보고 문턱을 유도한다.
- 글리프 식별 후 음표와 연결하는 단계에서 `glyph_id`, 원본 위치 증거, 직접/전파
  출처를 따로 보존한다. 전파는 음고 적용만 담당하며 현재 위치의 삭제를 허용하지 않는다.

이 접근도 분리되지 않을 수 있다. 특히 음표와 기호가 붙은 경우의 귀속이 핵심 미해결이다.
표본의 점수가 겹치면 억지로 삭제 조건을 만들지 않고 해당 경우를 보존한다.

## 구현 전에 통과해야 하는 대조

- 직접 오인식 9곳과 기존 전파 피해 9곳, 정상 삭제 7곳을 각각 식별한다.
- 1구간 진짜 ♮ 2개, 3구간 진짜 7개, 화음 `(1623,2144)`, 창 밖 ♮ `(1443,2384)`를
  필수 반례/대조군으로 넣는다. 미확인 121개를 정상이라고 가정하지 않는다.
- 최소 두 악보·여러 쪽으로 나누고, 일부를 모델/문턱 선정에 쓰지 않은 검증 쪽으로 남긴다.
- 임시표 분류 정확도와 후보 삭제의 정확도를 따로 센다. ♯/♮ 거부 뒤 ♭ 재선택,
  마디 내 전파 변화와 최종 음고를 전부 대조한다.
- 구현 뒤 정상 삭제 7곳 유지와 전체 라벨 좌표·값 대조, 18개 보호 검사 해제 상황을
  확인한다. 9개 지표 분리를 피해 음표 9개 복구로 대신 보고하지 않는다.
- 진짜 음표 오삭제를 만드는 후보는 기각한다. 골든을 갱신해 통과시키지 않는다.

이번 요청에 대한 결과는 **이 후보 제안과 기울기 문서 우선순위 반영**이다.
새 조건의 측정·구현 완료를 뜻하지 않으며 exe 빌드는 계속 보류한다.
